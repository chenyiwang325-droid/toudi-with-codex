# 内容与渲染契约

## 日程数据

**`schedule` 的母本为 `投递数据/日程数据.json`，日期精度不能靠显示补造。** 根结构为 `{schemaVersion:1,timeZone:"Asia/Shanghai",events:[],calendar:{enabled:false,calendarId:"",syncAll:false}}`。默认空白、未连接系统日历；使用公共 `manage` 入口及版本保护，不直接覆盖文件。

| 字段 | 契约 |
| --- | --- |
| `id` | 稳定唯一字符串，字母或数字开头，后续可包含字母、数字、`.`、`_`、`:`、`-`，最多 128 字符。 |
| `title`、`type`、`status` | 非空标题；类型 `application/exam/interview/preparation/review/other`；状态 `planned/completed/cancelled`。 |
| `start`、`end`、`allDay` | 未排期时二者为 `null`。全天日期为 `YYYY-MM-DD`，`end` 是不包含的结束日；单日可省略结束日。具体时间为带时区偏移的 ISO 8601，结束时间必须晚于开始。 |
| `timeZone` | 有效 IANA 时区；未提供时沿用工作区时区。 |
| `companyKey`、`prepId`、`reviewId` | 可选稳定关联键；没有关联时为空字符串，记录被移除不猜测替代关联。 |
| `location`、`url`、`notes` | 可选地点、HTTP(S) 链接、完整备注。标题最多 512 字符，备注最多 30000 字符；超出格式范围拒绝保存，不截断原文。 |
| `meetingInfo` | 可选入会信息文本，最多 2048 字符；接受会议号、密码、说明或链接，保留完整原文与换行。界面兼容读取旧事项的 `url`；仅当输入为完整 HTTP(S) 网址时写入 `url`。同步与 `.ics` 导出将入会信息写入备注，不把会议号当作 URL。 |
| `priority`、`estimatedMinutes`、`reminderMinutes` | 优先级 `0/1/2`；预计用时为正整数或 `null`；日历提醒提前分钟数为非负整数或 `null`，最多 43200 分钟。 |
| `syncToCalendar` | 旧版逐项同步标记，仅作兼容读取和原样保存；新界面不再逐项设置。`calendar.syncAll` 开启时此标记不限制同步范围。 |

**招聘截止是只读投影，自建事项是可编辑数据。** 截止投影没有写入第二份截止日期，不导出成用户自建事项。公共公司更名事务同时迁移日程中的 `companyKey`。取消保留原事项和稳定 ID，作为系统日历取消同步的依据。

**整份日程同步由 `calendar.enabled`、`calendar.calendarId` 和 `calendar.syncAll` 控制。** `syncAll` 为布尔值，缺省按 `false` 读取以保留旧版逐项范围。用户显式点击“同步日历”或“启用自动同步”后设为 `true`，全部已排期的自建事项随保存和工作区更新同步；未排期或缺结束时间的非全天事项暂缓。取消记录无需日期即可删除原有且归属确认的系统事件。停止同步保留范围设置及现有系统事件。未保存的编辑不参与同步；同步期间的新版本在当前批次结束后继续处理。

**系统日历绑定以工作区与事项 ID 隔离，并核对外部修改。** 同步入口只接收当前工作区标识与规范事项；不接收任意路径或命令。已完成事项保留历史，取消仅删除可证明属于 TouDi 的绑定事件；外部变更返回 `blocked`，未确认的时间不推造结束时间。

本文件描述当前解析器和渲染器真实支持的边界，供Agent按原子条目协作。业务事实、授权和写入规则以根AGENTS为准；本文件不授权批量改写材料。

## 公司准备结构（语法示意，不是业务示例）

```markdown
# {公司}{岗位}（{届别或批次}）面试准备
> {确有必要的信源说明}
## {一节的名称}
{该节必须前置的背景/概括}
### {独立条目标题}
{完整主答}
{该条目自己的追问备答、表格和引用}
```

app/脚本/9_面试准备导入.py `parse_doc`要求H1匹配带全角括号的准备标题，真实`## `切分sections；头部blockquote保留为headerNote，其余头部自由文本不会自动变成sections。因此要展示的有效正文放在章节内，不放H1与首个H2之间的普通段落。网页新建表单使用 `structured:true`，服务从公司、岗位与批次生成合法 H1，默认空章节可保存；用户无需手写标题语法。已有完整合法标题原文保留。

页面`ppSplitCards`把H3至H6每个标题或`**数字编号标题**`识别为独立卡，H3/H4不是嵌套父子目录。要让备答留在主答内，使用段落/加粗小标题，避免另起H4把它拆成独立卡；需要独立展开才使用标题。未识别编号保持正文，章节首个卡之前文字是intro。卡的title/sub/body、intro均保留。这项是现有解析实际行为，不能承诺任意Markdown层级自动树状化。

通用JSON的group是显式项目组，body由renderMd渲染；STAR、亮点、内容整理及问答三层靠条目/group组织，不能用短概括替换独立条目。搜索统一在当前准备模式全资料中匹配，命中携带原分类/公司与条目目标，打开原文并可回到结果；目录选择用于阅读，不缩窄搜索范围。草稿保存于当前页面内存，不擅自提交。

## 复盘结构

app/脚本/6_复盘导入.py按`## 一、`至`## 五、`切节，逐题节按`### Q{n}：{题目}`分块；字段为顶层`- 考察意图：`、`- 当时的回答：`、`- 面试官信号：`、`- 诊断：`、`- 改进版回答：`、`- 本题判断：`与`- 追问：`。诊断维度用明确前缀。字段可跨行，直到下一识别字段或题目；普通Markdown标题不替代这些结构字段。原答到位不要求改进稿，页面保留原文而非空占位。首次预检与导入用app/脚本/6_复盘导入.py，不把普通公司稿当复盘解析。

## Markdown和附件支持

`renderMd`支持H1–H6、段落、空行、blockquote、横线、带围栏代码、列表和带管线的表格。表格需表头、分隔行和连续管线行；不是完整CommonMark解析器，不承诺任意复杂嵌套/HTML插件。原始HTML按文本转义，不靠自定义HTML布局承载关键内容。链接/加粗等由mdInline处理；内容链接常态下划线。未知结构降级为普通文本，不能据此删掉母本内容。

准备相对附件路径从源Markdown的mdPath所在目录解析，不从HTML地址解析。prep_resources仅开放当前准备稿实际引用、位于工作区且非隐藏的允许后缀资料；不存在/未登记只提示，不能扩大任意文件访问。md/txt显示文字，PDF/DOCX提供提取正文；PDF原页按需加载。探查附件只开放目录登记Markdown。手机快照附件密文与正文种子分开，浏览器按需解密，只读，不探测本地API。

**Markdown 表格根据每列的可见正文分配宽度。** 短标签列保持紧凑，长说明列保持可阅读的行宽，不依据列位置固定放大最后一列；空间不足时在表格自身横向滚动，不挤窄正文或撑开整个阅读区。单元格内容完整保留，统一顶端对齐、字号和间距，支持表头分隔行中的左、居中、右对齐，以及转义竖线和行内代码中的竖线。该规则适用于通用准备、公司准备、探查、复盘、附件和资料预览。

1. 读最新母本，确认范围/id/关联/旧编辑；备份、业务hash、写前重读。生产可视验收只读；保存机制用隔离fixture验证。
2. 公司稿运行content_preflight --kind prep，导入app/脚本/9_面试准备导入.py单篇；复盘用--kind review和app/脚本/6_复盘导入.py。通用JSON更新保持id/无关字段，需要Markdown归档时由Agent从最新JSON导出，旧md不是反向真源。探查用对应预检及目录工具。
3. 核对分节、条目数、主答/备答/追问/来源及附件；读接口、实际页面搜索命中、独立展开和原文保留。有解析失败先修目标结构，不手写一份假产物掩盖失败。
4. 按明确授权及canonical流程构建快照。发布只允许stage，核对远程hash/解锁/资料/只读；当前轮若要求先验收，先不部署。

验证命令：`python3 -m unittest discover -s tests -v`在隔离临时工作区验证发布、实际预检/导入、保存冲突、加密构建解密与源码空模板；实际UI通过各模块阅读、搜索和附件检查。测试结构占位不构成业务示例库。复杂列表、数学公式或HTML版式若超出现有能力，先说明降级，必要改渲染器并相称测试，不批量重写正文。


## 工作区文件和字段

投递记录.json为记录数组；基础字段集合：名称、校招类型、行业、性质、录入时间、截止时间、岗位、地点、应届生、学历要求、公告链接、网申链接/邮箱。基础字段值为字符串，名称非空，未知字段不擅自塞入。链接保持用户原信源；名称相同多记录按公告链接或记录顺序生成名称｜来源键，Agent发布前核对旧键。RAW_DATA模板永久空，不在源码里落用户记录。

已核实的汇总记录可以额外包含字符串“归并类型”和数组“归并来源”。每个来源保留上述基础字段与可选字符串“编辑键”，名称非空，不能嵌套汇总；来源编辑键用于查阅原主体的独立标记，不自动传播给汇总记录。发布工具保留并校验这些信息，不为满足字符串字段要求丢掉原来源、入口或标记关联。是否归并仍由用户的信源和身份规则决定。

用户编辑数据.json是{edits:{记录键:{status?,starred?,excluded?,note?,research?,researchNote?,fields?}},pref:{natures?,industries?,education?,cities?,jobs?,…}}；未投递/已投递/笔试/面试/已通过/已拒绝/已截止为准确当前标记。pref是用户偏好，不是自动排除指令。API返回version，POST需要同一GET的base，版本字符串不转浮点数。

通用准备是{categories:[{id,name,items:[{id,title,body,group?,qa?,source?,updated?}]}]}，由Agent按用户资料直接维护或网页编辑，无默认分类/业务示例库。公司准备是{preps:[…]}，复盘是{sessions:[…]}。运行时缺文件表示空集合，文件损坏表示错误不可覆盖。

探查目录为{companies:[{id,company,title?,file,researchedAt,aliases?,attachments?:[{file,label}]}]}；file/attachment.file相对岗位探查目录，必须在目录内存在。报告正文Markdown保留原证据，日期YYYY-MM-DD。网页/快照只读取已登记内容，不递归扫描任意资料。

## 附件降级

PDF正文提取依赖可选pdftotext；缺工具时显示说明并保留原件，不能把“没有提取文本”解释为“文件没有内容”。DOCX读取ZIP内document.xml，图片/PDF原页保留下载或嵌入；不保证复杂排版全文等价。文件白名单与相对路径限制实际由prep_resources.py/safe_path实现。

探查登记附件目前为Markdown专项/归档；API与快照按文本读取，不宣称任意二进制探查附件可直接预览。PDF/DOCX原件由公司准备引用路径提供。

## 详情与偏好分类

**详情按“招聘信息 → 投递跟进 → 相关材料 → 日程安排”连续阅读，操作属于对应信息区。** 固定标题栏只负责公司身份、前后记录导航与关闭。招聘信息先展示完整岗位、地点、截止时间、届别和学历，再提供主操作“投递入口”与次操作“招聘公告”；企业信息与来源按需展开，字段修改在该区完成。投递跟进分为进度与个人标记两组，控件统一 34px 高，原生选择框的箭头居中；备注与待核实事项按需展开并保留完整内容。相关材料使用同宽的导航分段，只显示岗位探查、面试准备、面试复盘及跳转箭头，不附数量或状态小字；窄窗口改为逐行导航。日程安排独立展示关联事项，并在区内提供“添加日程”，进入编辑器填写具体日期与内容后才保存，不因导航创建事项。

**详情保留同一数据、关联与编辑契约。** 材料点击后按稳定公司键或明确关联定位实际模块，按需读取；通用准备和弱项追踪保持在各自主模块，详情不重复提供。原始字段仍是记录真源；长文本不压缩，字段覆盖可查看原值。关联日程通过稳定公司键读取并提供返回日程的入口。标记变化、外部更新和前后记录切换保留适用的输入、展开状态与阅读位置。外部入口仅为 HTTP(S) 或明确邮箱生成链接，其他来源文本完整保留。

**全局设置只有侧栏入口，搜索与详细筛选只有记录总览右侧入口。** 侧栏底部以太阳、月亮和电脑直接选择浅色、深色和跟随电脑，整个分段控件与侧栏导航左右对齐，三个选项等宽且图标居中；选中使用中性表面和轻微阴影，支持左右方向键，继续沿用工作区外观配置。连接正常或正常保存时隐藏底部提示，仅未连接、读取／保存失败或冲突时显示相关操作。表格、看板、统计与刷新位于当前页面顶部；资料更新正常时无常驻状态按钮，待处理或读取失败时才显示可展开说明。记录数量、筛选反馈、新增／导入和表格显示列共用紧凑工具行；已有记录仍在详情修改。准备、探查、复盘保留各自的导入入口及原有保存、版本保护和冲突恢复。

**招聘记录入口只负责新增与导入／导出，不再次列出全部记录。** 新增表单点“保存记录”后，内部按原有 dry-run 校验和版本保护提交，保留完整字段、自动草稿与恢复副本；普通新增不显示独立检查或 JSON 预览。导出记录实时读取已保存的招聘记录数组，下载 JSON 文件，不包含编辑草稿或其他模块。导入记录按现有全量替换契约执行：选择 JSON 数组后先自动校验，明确显示文件条数、当前替换范围，并最多预览前五条；点击“确认导入”才写入，关联冲突及版本变化不覆盖。草稿导出和 Agent 任务复制不出现在招聘记录的日常操作页；仅确有未保存记录时提供继续编辑入口，设置中的协作流程与异常恢复能力保持可用。

**偏好分类是阅读和匹配层，不回写信源字段。** 默认规则统一维护于 app/assets/preference-defaults.json：企业性质归并常用同义词；行业按“大类 → 细分方向 → 小类”组织；学历按通用层级与明确范围匹配。“硕士研究生”等同义词归并，“及以上”按范围匹配，不将“研究生”直接断定为硕士。MBA、分岗位或不明要求保留原文并兜底保留，不能因为普通学历选项将其排除。

**信源差异通过工作区规则修正，默认分类继续可用。** 冷启动对照原始信源清点实际原词，修正有依据的行业映射、分隔符、同义词与学历范围，保存到 settings.preferenceRules。地区、招聘项目和企业性质不作为独立行业选项；未知行业保留为待核实，不推断适合或排除，不改变记录格式。

保存未改动的选项时保留原偏好值；新勾选的合并项覆盖已知别名，取消对话框不写入。历史偏好中当前信源没有的值仍可查看和取消。“适合我”的逻辑为企业性质或行业命中，并满足学历条件；未注明学历的记录沿用保留规则。分类名称不作为招聘资格结论。

运行 `node tests/test_preferences.cjs` 验证别名、不同学历门槛、歧义行业、历史偏好和保存往返；私有实例另核对信源词条覆盖及业务母本未变。

## 在线实例与 Agent 同步

**在线实例沿用同一套规范文件和解析器。** hosted.py 处理登录、同源与会话保护；remote_files.py 仅向 Agent Token 开放受限资料路径。HTML 在经过登录保护的服务请求中注入 hosted 标识，浏览器连接同源 API；模板仍保留空 RAW_DATA，静态阅读版仍只读。

`GET /api/agent/files` 返回文件列表、SHA256 版本和大小；带 path 查询时返回指定允许文件的版本及 Base64 内容。`POST /api/agent/files` 接受 changes 数组，每项含 path、base、contentBase64，整批验证后在同一资料锁内提交并保留恢复副本。存在任何版本冲突时整批返回 409；不得换 base 盲重试。资料同步不提供 shell、源码或任意目录访问，也不通过该接口删除文件。

网页修改仍使用其 collection version，Agent 文件同步使用 SHA256；两者读取和更新同一持久工作区。准备的 mdPath 应相对工作区，附件路径相对准备稿所在目录，跨本地资料副本与云端实例保持一致。未知信源格式先由 Agent 转成原有规范，云端接口不充当招聘抓取器。
