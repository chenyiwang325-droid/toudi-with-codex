# 桌面安装与使用

**普通用户从 [GitHub 桌面 Release](https://github.com/chenyiwang325-droid/toudi-with-codex/releases/latest) 选择对应系统与架构的安装包。** App 包含业务运行组件，打开后使用现有中控台界面，不需要手动运行 Python 或终端服务。

## 下载与安装

**按 Release 说明选择文件，核对版本、架构、校验值与已知限制。** macOS 选择 Apple Silicon 对应文件；Windows 已提供 CI 构建模板，构建结果以实际任务为准，仍待实机验收。其他架构只有在对应发布包及验收说明存在时才视为支持。

**macOS 测试包使用临时签名，尚未正式公证。** 系统可能要求确认或拦截首次下载的应用；按系统提供的安全流程与 Release 说明处理。无法确认来源或无法打开时保留错误信息反馈，不以关闭系统安全保护作为安装步骤。

**v0.4.0 Apple Silicon 包名为 `TouDi_0.4.0_macos_arm64.zip`，以最新 Release 实际附件为准；下载对应包，解压后将 `TouDi.app` 放入应用程序文件夹并打开。** ZIP 内是完整应用，源码压缩包不是安装包。更新时替换应用，个人工作区继续保留。

## 第一次打开

**新用户从独立空工作区开始，已有资料可原地接入。** 可以手动新增资料、导入规范文件，或按[Agent 接入](Agent接入.md)让本机 Codex 整理内容；不要求加载示例数据。当前资料位置以 App 接入说明显示的路径为准。默认 macOS 为 `~/Library/Application Support/TouDi/workspace`，Windows 为 `%LOCALAPPDATA%/TouDi/workspace`，Linux 为 `$XDG_DATA_HOME/toudi/workspace`（未设置时采用系统默认数据目录）。

**日常维护在四个业务模块完成。** 投递管理维护岗位与进度，准备分开管理通用和公司资料，探查管理报告与附件，复盘管理真实场次与问答。模块操作与格式见[编辑与保存](编辑与保存.md)。

**保存后核对状态和实际正文，退出重开后仍应读取同一资料。** 若提示版本冲突或格式错误，保留当前候选，读取最新内容再处理；错误不应被当作空工作区。未提交草稿与正式保存分开管理。

## 使用已有工作区

**选择“选择已有工作区”，绑定验证过的资料目录。** 设置不需要填写复杂路径表单；已有旧格式先让 Agent 按[原地接入流程](备份与迁移.md#原地接入已有工作区)预览、备份、转换和校验，再选择目录。绑定不复制正文，不把资料移入安装包。

**绑定后 App、源码浏览器与 Agent 读取同一个母本。** Agent 保存后，打开中的 App 自动显示新资料；回到窗口时立即检查，也可点顶部“刷新资料”。后台检查保持安静，不改变按钮状态；待显示的更新与读取问题在“刷新资料”旁的状态入口查看，不在列表上方插入通知条；资料未变化时保留当前内容和阅读位置。手动刷新显示进度，按钮尺寸保持一致。正在编辑的板块保留草稿，结束编辑后自动读取更新；其他板块继续刷新。仅打开详情查看不会阻挡更新；实际未保存的编辑继续保留。某一模块读取失败时保留旧内容并自动重试，不将它标记为已同步，也不阻挡其他模块。程序版本升级后需重启一次，日常资料更新不需要。空工作区、筛选无结果、加载中和读取错误有不同状态；读取错误不能当作空库覆盖。

**工作区绑定跨应用重启保留。** 显式 `TOUDI_WORKSPACE` 优先于绑定配置；开发隔离目录不会自动成为正式母本。无绑定时仍可使用 App 默认空工作区，解除绑定不删除旧资料。

## macOS 权限保留

**工作区、日历连接配置和系统权限是三项不同的持久记录。** TouDi 保存工作区与日历目标；macOS 保存“文稿”及日历授权，App 不以本地开关代替系统授权。已获完整访问时，检查、同步和再次连接不会重复调用权限申请。

**临时签名的程序更新可能改变 macOS 用于识别应用的身份。** 同一安装包正常重开应继续使用已有授权；重新构建或替换了临时签名程序后，系统可能再次询问。这属于安装身份变化，不能通过复制资料或重新绑定工作区解决。

**自行维护本机版本时，可让 Codex 配置一个仅用于本机 TouDi 的固定签名身份。** 这是可选的免费维护流程，需要用户明确允许建立本机代码签名证书及其信任设置；私钥保存在用户钥匙串，证书信任限定为 `/usr/bin/codesign` 的代码签名策略，不设为通用证书根。签名记录保存在 TouDi 的本机配置目录，不进入仓库或公开安装包。

1. 用户确认建立本机签名身份，并结束未保存编辑。
2. Codex 用本仓库 `desktop/scripts/install_macos.py` 安装已核验的 ZIP，首次附加 `--setup-local-signing`。如出现系统证书或钥匙串确认，由用户本人完成。
3. 在签名切换后的首次启动中确认文稿和日历访问，检查已绑定工作区与原日程。
4. 正常退出并重新打开至少两次，核对同一工作区、系统日历授权及没有重复提示。
5. 后续同机更新继续使用该安装脚本；它自动复用已建立的身份，不重新生成证书。签名或配置损坏时保留现场并修复，不能静默回退到临时签名。

**本机固定签名不能替代面向所有下载用户的正式发行签名。** 公共 macOS 发行应使用发布者的 Developer ID 与公证；自签身份只用于自己的本机维护，不作为已通过 Apple 公证的证明。更换电脑、删除证书或用户撤销权限后，需要重新建立对应授权。

## 备份、更新与其他设备

**更新前导出完整备份，再替换应用。** 不删除工作区来升级；版本变更和平台支持以 Release 为准。已有资料迁移与恢复见[备份与迁移](备份与迁移.md)。

**其他设备可访问你另行发布的加密只读查阅版。** 该网页只展示最近发布版本，桌面保存后需再次发布；发布并不是默认开机步骤。源码运行和发布说明见[首次使用与部署](首次使用与部署.md)。

## 资料位置与查阅版导出

**在桌面设置中选择“打开资料目录”，即可查看当前正式工作区。** 在该目录外另存备份，不直接编辑安装包资源，也不将工作区复制进公开仓库。

**其他设备查阅属于可选部署流程，由本机 Codex 按部署文档处理。** 普通设置不提供加密导出；需要时使用资料工具的 `export-reading` 命令生成只读产物，再发布到自己的静态托管。它与换机备份不同，操作和保存范围见[首次使用与部署](首次使用与部署.md)。
