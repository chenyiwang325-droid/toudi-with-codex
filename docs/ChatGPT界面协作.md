# 用 ChatGPT 查看和复核界面

**Codex 取得当前 App 的截图，ChatGPT 通过已有只读连接读取图片、功能结构与界面状态。** GitHub 提供源码和通用文档；用户真实界面保存在自己的私有工作区，不需要把资料上传到 GitHub，也不需要另建一个 TouDi 连接服务。

## 开始协作

**已有 codex-with-chatgpt 连接直接复用，先验证远端会话能读取当前工作区。** Codex 按该 Skill 恢复对应连接，再让 ChatGPT 调用 `workspace_info`，核对工作区名称。连接组件须提供 `read_image`，返回实际图片内容；`read_file` 读取截图文件名不能代替图片读取。账号登录和授权使用用户原有 ChatGPT 方式，不另外调用模型 API。

**首次界面任务先指定页面和共享范围，再获取截图。** 可以告诉 Codex：“让 ChatGPT 查看投递管理和一条详情，分析布局和功能组织；截图只用于私有协作。”Codex 在当前 App 中只读观察，不为截图修改记录、偏好或信源；正在编辑或进行测评时先保留原窗口状态，不能擅自重启或抢占窗口。

## 获取一组可核对的界面资料

**截图、状态和功能说明属于同一组快照，必须能追溯到获取时间。** 通过可用的原生界面工具，在投递管理表格和详情加载完成后分别取得截图与完整 Accessibility 状态，保存到仓库外的私有目录。图片文件名为 `management.png`/`management.jpg`、`detail.png`/`detail.jpg`，状态文件为 `management.ax.txt`、`detail.ax.txt`。读取工具需关闭差分，确保文件包含当前完整状态；不要把另一轮截图与当前状态混合。

**`ui_review.py` 只组织这组资料，不读取业务母本，不控制 App，也不上传文件。** 源码命令如下；安装用户由 Codex 在已打开的源码工作区执行这一步，不要求用户重新配置 App 的数据目录。

```sh
python3 app/ui_review.py \
  --workspace /path/to/connected-workspace \
  --capture-dir /path/to/private-captures \
  --output /path/to/connected-workspace/private-review/session-01 \
  --app-version 0.6.12
```

**输出包含两张截图、`manifest.json` 和 `structure.json`。** 图片扩展名按实际格式识别；清单记录像素尺寸、时间、图片 SHA256、观察到的 App 版本以及各页状态。状态只提取固定的控件标志，例如详情是否打开、折叠区是否展开、上一条是否可用；不复制 Accessibility 原文、筛选内容、记录值、链接、目录或凭据。功能结构说明页面职责，并对应当前界面的模块与源码位置。

**输出目录必须在已连接的私有工作区内，并且位于所有 Git 仓库之外。** 程序拒绝仓库内路径和已有输出目录，避免误提交或把新状态写入旧证据。原截图及原 Accessibility 文件同样留在私有目录；它们可能包含用户实际记录，不属于公开展示素材。

## 验证 ChatGPT 确实看到了界面

**验收须在实际 ChatGPT 会话完成，不能只检查本地图片或工具返回成功。** Codex 给出清单的工作区相对路径；ChatGPT 用 `read_file` 获取清单，再对两张截图分别调用 `read_image`。第一次先只根据图片回答以下问题，不把答案预先写进提示：

1. 投递管理采用什么布局，搜索与筛选位于哪里，底部外观入口如何排列？
2. 详情从上到下有哪些分区，链接是什么视觉形式，哪些区块处于折叠状态？
3. 哪些内容确实可见，哪些在当前截图中无法判断？

**再读取功能结构和状态，解释“入口 → 操作 → 结果”的关系。** 至少核对检索与详细筛选、详情材料跳转、添加日程这三条路径；根据清单时间明确说是在审查这组快照。Codex 将回答与同一次实际观察比对，记录图片读取成功、理解正确、理解偏差或证据不足；不能将模型的建议当作交互已测试。

## 后续更新与边界

**界面变化后由 Codex 重新获取一组快照，再让 ChatGPT 读取新清单。** 该方式按任务获取界面，没有持续监控屏幕，也没有远程点击、保存或提交权限。静态截图不能证明搜索、保存、日历同步或其他实际操作成功；交互仍由 Codex 在授权范围内执行并读回验证。

**真实资料只用于用户批准的私有协作，公开仓库只保留此流程、通用工具和合成测试。** 不将私有快照、会话回复、访问地址或业务母本提交到 GitHub、Issue、README 或 Release。公开展示继续使用专门的虚构资料，边界见[隐私与公开发布](隐私与公开发布.md)。
