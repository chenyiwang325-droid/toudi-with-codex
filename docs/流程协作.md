# 原子流程与 Agent 协作

网页负责阅读、检索、标记和可控保存。Agent 在用户自己的工具环境中处理信源、资料与更新；这六个流程独立，用户可替换读取工具与研究方法，不需要复刻作者的来源。每次先读根 AGENTS.md 和最新母本，明确范围；有必要写入时使用文件锁、原子替换和可恢复副本。

## 云端任务的共同步骤

**在线实例先拉取、后处理、再同步。** Agent 通过环境中的 TOUDI_REMOTE_URL 和 TOUDI_AGENT_TOKEN，使用 `app/脚本/remote_workspace.py pull --workspace 资料副本目录` 获取当前母本。将 TOUDI_WORKSPACE 指向该副本，执行下文的独立任务；结束后用 status 核对修改范围，再 push。准备、复盘解析与探查目录规则沿用原契约，不要求用户的信源与作者一致。

发生 409 时保留当前候选，拉取另一份最新副本并对账；不改 base 强推。网页和 Agent 共用实例持久工作区，未变的文件不提交。具体授权和命令见[云端部署](云端部署.md)。

## 投递记录更新

输入：用户指定的信源、当前规范记录、标记与发布日期证据。步骤：读取范围→将源字段映射到 docs/内容与渲染契约.md 的规范字段→保留原链接与完整岗位文本→对照旧记录/身份键/标记→生成候选→验证→按当前 SHA 发布。运行 `python3 app/脚本/publish_records.py CANDIDATE_JSON --base CURRENT_SHA`；首次base为`missing`，替换空数组另需`--allow-empty`。输出：投递记录.json、变更与无法确认项。校验：基础字段都是字符串，汇总来源按内容契约保留独立入口和编辑键；无凭空判断/日期、归并后原文仍可达、旧标记不被误移。命令不会修改用户编辑数据，但Agent仍须核对记录删改对旧键的影响。失败：保留候选；SHA变化停止发布并读差异；备份用于明确恢复。

本仓库不包含飞书抓包/登录/特定届别日期校准脚本，也不把某个表格当默认源。飞书、表格、招聘站、个人文件均是用户 Agent 的可选读取 adapter，其责任是输出规范数组和证据；不是浏览器内通用导入器。`publish_records.py`只接受已规范的产物，不解析外部来源。

## 岗位探查

输入：指定公司主体、投递岗位、用户关心的问题。步骤：主体与岗位边界→官方岗位/待遇→其他可信来源与时间→结论和证据分层→一公司主报告→登记目录与附件。输出：工作区/岗位探查/主报告.md 与 探查目录.json；需要消除待查标记时只动目标research字段，保留进度与其他字段。验证：同公司不重复、researchedAt为真实调查日、所有登记附件路径在工作区内、未知/推断明确。失败：保留未覆盖项，不以mtime伪造日期，不把报告塞进公司准备。

## 面试准备

输入：真实简历/经历、JD、用户指定公司或通用主题、已有准备。步骤：明确本场考察→事实与证据→可独立口述的主答→追问备答→独立条目→导入与阅读验证。通用内容写逐字稿数据.json；公司稿按契约写在面试准备/，然后 `python3 app/脚本/9_面试准备导入.py PATH --company "公司" --position "岗位"`。公司背景与JD前置，通用项目/行为题统一维护，避免复制成每公司一套。输出：Markdown母本与公司准备派生JSON；验证题目独立搜索、正文/备答/表格/附件不丢、companyKey准确；公司准备网页只读；同id重导前重新读取最新Markdown母本并核对派生记录，避免覆盖较新的原稿。失败：补缺口，不编经历，不把旧文档归档后继续残留重导。

## 面试复盘

输入：完整逐字稿/纪要、真实场次信息、已有相关材料。步骤：还原问答追问→判断是否回应与证据足够→整场少数关键要点→逐题证据→只对实质缺口给改写→按契约导入。运行 `python3 app/脚本/6_复盘导入.py PATH --company "公司" --position "岗位" --round "轮次"`。输出：复盘Markdown及JSON场次、弱项依据；验证完整问答、全场判断前置、没有从时长推断录用结果、基本到位题不强制改写。失败：保留缺失录音/材料，不猜原答；同id覆盖前备份并读最新网页版本。

## 明确请求后的内化

输入：用户明确指定的复盘题/主题、最新通用准备、已确认事实。步骤：识别实质可迁移的缺口→寻找现有条目→目标内更新→保留STAR/亮点/详细素材与备答→去重→验证。输出：通用准备JSON目标项；保留稳定id/category/group。验证与用户要求同范围，不把内部口径核对或Agent指令导入候选人正文。失败：保存候选，素材不足先报告；复盘结束不自动启动内化。

## 手机同步

输入：已确认工作区、用户口令和托管目标。步骤：读取一致母本→构建加密快照→核对stage白名单→按授权只部署stage→生产hash/解锁/只读/附件验收。输出：个人本机密文产物，托管副本（有授权时）；禁止把密文当公开源码资源提交GitHub。失败：构建失败不部署；保留上一可用快照；本机材料不因手机失败被回滚。参数和具体命令见首次使用与部署.md。

## 写入方式

网页标记、通用准备、复盘写入通过同源API，使用GET版本作为POST base，409保留草稿。Agent文件更新与服务共用工作区/投递数据/.update-data.lock；单文件原子替换，多文件任务要先备份全部目标、校验候选、串行提交并记录恢复路径。不擅自写全表标记。标记edits/pref、通用categories、公司preps、复盘sessions及探查companies的字段见内容契约。
