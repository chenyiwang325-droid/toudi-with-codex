# Chrome 辅助填报

**辅助填报是 TouDi 投递中控台的浏览器扩展，在当前招聘网页识别、核对、填写和读回表单。** 中控台管理求职任务和正式填报资料；扩展执行当前网页操作。App、扩展与 Agent 共用工作区 `填报资料/资料.json`，扩展在未连接或离线时也可维护本地资料。

**当前版本为 v0.5.2，升级时同时更新扩展和浏览器连接工具。** 从 [最新 Release](https://github.com/chenyiwang325-droid/toudi-workbench/releases/latest) 下载工具包，用扩展文件替换原目录后在 Chrome 扩展管理页点击“重新加载”，再运行包内连接安装程序。不移除扩展，不重新导入资料。弹窗与扫描后的引擎版本应均为 0.5.2；旧计划需要重新识别。

## 安装与首次配置

**首次使用先建立自己的资料，再自行选择是否接入 Agent。** 从 [最新 Release](https://github.com/chenyiwang325-droid/toudi-workbench/releases/latest) 下载 `TouDi-browser-macos-arm64.zip`；仅需要基本填写时也可下载 `TouDi-filling-extension.zip`。

1. 解压工具包。在 Chrome 的 `chrome://extensions` 开启开发者模式，点击“加载未打包的扩展程序”（部分版本显示为“加载已解压的扩展程序”），选择 `TouDi-filling` 文件夹，并将插件固定到工具栏。
2. 要与 App 共享资料时，运行包中的“TouDi 浏览器连接”安装程序一次，在插件“资料与设置”中显式连接当前 TouDi 工作区。已有浏览器资料与工作区资料不一致时先核对双方，再选择保留或合并；不依赖模型登录。未连接也可先用标准表单填写，已有私人资料包可导入。
3. 打开“Agent 协作”，选择自己的协作方式。基本识别和手动选择资料不需要模型，可选择“暂不接入 Agent”。
4. 若选择“本机 Codex”，确认已安装本机连接工具；安装官方 Codex 客户端并用自己的 ChatGPT 账号登录。点击“检查连接与模型”，从当前客户端返回的目录选择模型，保存协作设置。
5. 若选择“使用自己的 Agent”，保存设置后使用复制任务、导入结果的方式；模型协作不需要本机连接工具，连接工作区资料时仍需要。

**模型由用户指定，之后可在协作设置中更改。** 不默认指定 Luna，不使用 CLI 默认模型，也不因模型不可用而自动替换。自动核对默认关闭，只有用户主动开启后，识别才会对歧义字段调用所选模型。本地计划先显示，模型在后台核对；等待期间可先填写已确认字段。模型结果不会覆盖后续的手动匹配或已完成的填写报告。旧版已明确开启自动 Luna 的设置保留为用户既有选择，仍可更改。

| 协作方式 | 使用条件 | 日常操作与费用 |
| --- | --- | --- |
| 本地规则与手动匹配 | 已保存个人资料 | 识别、选择、填写与核验，无模型费用 |
| 本机 Codex | 连接工具、官方客户端、ChatGPT 登录、已选模型 | 插件直接核对歧义，使用现有 Codex 额度，无 API Key 或新增模型服务 |
| 自己的 Agent | 用户已有的 Agent 工具 | 复制任务给 Agent，再导入返回的 JSON；使用方式与费用由该工具和账号决定 |

**“检查连接与模型”只读取登录状态和模型目录，不发起模型生成。** 工作区资料连接是独立操作，只通过本机工具读取当前绑定资料。 模型目录不保证账号本次可调用；实际核对成功才证明该次接通。模型不可用、超时或额度受限时保留本地计划。连接工具由 Chrome 按需启动，日常无需打开 TouDi App 或终端。

连接工具负责本机资料同步和所选模型调用；升级保留原绑定和资料。

当前发布验证 macOS Apple Silicon。安装包为临时签名，未进行正式公证；其他平台可阅读源码，尚未完成安装包与真实浏览器验证。

## 从中控台进入填报

**中控台左侧“扩展功能 → 辅助填报”提供填写资料、安装指南和扩展入口。** 已安装扩展时，点击“Chrome 连接与设置”直接在 Chrome 打开资料库；尚未安装时按入口中的指南操作。

在 App 的“填报资料”使用标准表单维护内容；扩展首次显式连接后共享同一母本。正式文件不存在时兼容读取根 `网申信息库.json`，首次保存建立 `填报资料/资料.json` 并保留旧文件。私人导出用于备份或离线交换，不再作为日常更新的必经步骤。Agent 通过公共 `profile` 管理入口读取版本、校验候选、提交和读回。

**扩展中的“打开投递中控台”用于返回已安装的 App。** 此入口通过本机连接工具打开固定 TouDi App，不依赖模型登录；尚未安装工具或 App 时，可查看旁边的安装与使用指南。网页填写不会自动提交申请或修改中控台投递状态，网站提交完成后再确认对应记录。

## 填写自己的资料

**资料库预设通用字段和输入控件，具体内容由每个用户填写。** 首次打开只有一套“默认资料”，没有作者的个人信息、经历或求职方向。空白字段不参与自动填写，也不要求先编写 JSON。

| 模块 | 填写内容 | 操作方式 |
| --- | --- | --- |
| 个人信息 | 姓名、手机、邮箱、居住地、性别、出生日期；证件、最高学历和个人评价等按需补充 | 填写一次，之后直接编辑 |
| 教育经历 | 学校、学历、专业、学位、起止日期；学院、学习形式、GPA 和课程等选填 | 按学校／阶段逐段添加 |
| 工作与实习 | 单位、岗位、部门、地点、起止日期、工作职责；工作类型与成果选填 | 每段经历单独添加和编辑 |
| 项目经历 | 项目名称、角色、日期、描述、本人职责；成果与链接选填 | 每个项目独立管理 |
| 语言能力 | 语言／证书名称、熟练程度、成绩；取得日期选填 | 可以添加多种语言或证书 |

1. 使用各模块的“填写”或“添加”按钮，完成一份资料或一段经历。文字内容直接填写，学历等常用选项直接选择；选项不适用时选择“其他（自行填写）”。
2. 日期选择“年月”或“具体日期”，按实际信息填写；工作和项目尚未结束时勾选“仍在进行”。程序不为只有年月的资料补造具体日。
3. 常用字段之外的信息，使用“自定义字段”或经历内的“补充自定义字段”。先选择所属模块和已有经历，再填写名称与内容，经历标识由程序维护。
4. 保存后回到招聘网页重新识别。可用“编辑整段资料”更新一段经历，单项别名、GPA 满分、人工确认等设置放在展开的“补充字段与单项约束”中。

**一套资料即可开始使用，多个版本仅在需要不同简历内容时建立。** “管理版本”支持自行命名、复制当前版本和删除不再使用的版本；复制产生独立资料，修改副本不会改动原版。导入包已有的版本名称与字段归属按原数据保留，不用作者的求职方向替代用户设置。导入资料存在共享字段时，编辑窗口会说明其影响范围。

## 在招聘网页填写

**先核对计划，再填写自己确认的字段。** 插件只在用户操作后访问当前招聘网页，按标签、分组、经历提示和选项识别。

1. 在招聘网页点击插件，选择本次资料版本，再点击“识别当前页面”。页面分别显示扫描与本地计划耗时；打开插件先读取浏览器资料，识别时再核对工作区同步，连接超时则明确提示使用本机副本。
2. 查看分组计划：可填写、已有一致、已有内容冲突、需选择记录、资料待补或需人工操作。
3. 有歧义时，用已配置的模型核对，或复制任务交给自己的 Agent，粘贴返回的 JSON 后点击“导入并重新核对”。也可直接手动选择已有资料键。
4. 勾选字段，点击“填写所选字段”。已有不同内容默认保留，明确选择覆盖后才修改。
5. 查阅逐项读回结果，在招聘网页保存草稿、上传附件、处理验证码与协议，最后由自己决定提交。

**读回一致表示当前控件保留了内容，不代表网站服务器已保存。** 报告持续标明网站保存未确认，不把填入成功改成投递状态。页面、资料或结构变化后重新识别；计划十分钟过期。校验失败、读回不一致和未执行字段分别列出。

## 平台识别与控件操作

**平台适配负责读取字段与操作控件，Agent 负责处理语义不明确的部分。** 当前包含通用表单、Moka 与 Zhiye / Phoenix 适配器；弹窗会显示本次命中的平台。字段标题与已有填写值分开读取，重复经历保持独立分组。

| 控件 | 操作与核验 |
| --- | --- |
| 原生日期、单选和下拉 | 检查格式、选项及限制，填写后读回 |
| Moka 普通下拉、拆分年月 | 展开对应字段菜单，选择唯一等价选项；年月取自已确认的起止日期 |
| Phoenix 自定义单选 | 对应唯一选项，检查禁用状态，再读回选中项 |
| Phoenix 搜索下拉 | 只操作刚打开的菜单，查找唯一选项并点击“确定”，核对保留值 |
| Phoenix 地区选择 | 搜索地区，通过选择图标选中，点击“确定”；同名不唯一时转人工 |
| Phoenix 日期 | 输入有日精度的完整日期并确认，核对实际保留日期；只有年月时不补造具体日 |

**结构辅助先提供候选，再接受 Agent 的选择。** 无法可靠确定标题或分组时，引擎仅提取附近的标题候选，Agent 返回候选 ID，本地验证后重新生成计划。已通过校验的结构规则按网站、路径、引擎版本和结构指纹复用；页面结构变化后失效。不接收生成的脚本、选择器或个人事实，未识别的复杂控件不会因 Agent 建议而强行执行。

**结构辅助和资料核对分别显示进度与结果。** 已配置本机 Codex 并开启自动协作时，先完成必要的结构辅助，再核对资料歧义；本地计划先显示，模型调用不阻塞查阅。也可复制结构任务给自己的 Agent 后导入结果。执行期间若用户改动匹配、清除计划或页面值变化，旧结果不再采用。

多选集合、任意级联、未明确结构的日历、附件和网站提交不在本次自动操作范围内。已填内容仍需明确选择覆盖；读回失败会报告失败，不视为网站已保存。

## 资料保存与更新

**正式工作区为共享母本，Chrome 保存可离线使用的副本。** 首次点击连接后，扩展在读取、保存与识别时同步并读回；用户可主动重新同步或断开。App、扩展与 Agent 的已同步修改进入 `填报资料/资料.json`，不使用 Chrome 云同步，也不宣称完整云端同步。

离线或连接失败时，修改留在 Chrome 并显示待同步；恢复连接后核对双方版本。无冲突变更可合并，同一字段修改不同或工作区变更时保留双方，先审阅再选择；不会通过替换基准静默覆盖。卸载或迁移扩展前导出私人备份。App 完整备份不包含 Chrome 尚未同步的修改，不能据此清除浏览器副本。

插件支持分模块查阅、搜索、整段经历与补充字段的新增／编辑／删除，以及按需维护别名、适用版本、日期精度、GPA 满分、人工确认和填写规则。保存检查资料版本，更新后旧计划失效。

**经历按开始时间倒序查阅，稳定标识与简历口径保持一致。** 教育、实习与项目分别排序；缺少可靠日期的记录排在后面，彼此保留原序。展示顺序不会让 Agent 自动猜测网站中没有名称的经历卡片。

**进行中的经历保存「至今」，具体日期只是已授权的表单占位。** 项目或实习的结束日期可设置 `ongoing: true`。网站支持「至今」的文字或等价下拉选项时直接使用；只有必须填写日期、且用户已选择 `dateFallback: "today"` 时，才使用填写当天。计划会说明占位性质，母本继续保存「至今」；日期超出网站限制时转人工核对。网站提供「至今」勾选时先手动选择，再重新识别。

**不同经历和资料版本必须有明确归属。** 模型不能按卡片顺序猜测本科、硕士或实习。资料中没有记录证据时保留待选，用户可手动确认。版本名称由用户决定，表单负责保持各段经历的字段归属。

自然语言规则供计划确认时核对。日期、记录归属、GPA、长度、选项与已有值保护由程序检查；其他文字要求不能直接视为已经自动执行。

## Agent 接入与资料结构

**资料核对返回已有资料键，个人事实由浏览器本地取值。** 任务包含待匹配标签、分组、选项、候选资料键和必要经历标签，不携带填写值与网页现值。网页文字作为不可信数据，本机 Codex 的 shell、浏览器、应用和插件工具关闭。

返回格式为纯 JSON 对象：`{"fieldId":"factKey"}`。插件再次检查模块、语义、经历、日期、长度和选项，模型映射不能绕过约束。记住的匹配只在网站、路径、结构与简历口径一致时复用；最近核验保存状态元信息，不持久保存实际填写值和 URL 查询凭据。

**资料包包含已确认事实、经历关系和适用条件。** 根对象为 `schemaVersion: 1`，包含 `facts`、`rules`，以及 `profiles` 版本定义和可选的 `savedAt`、`name`、`supplements`。不提供作者资料或示例经历。

| 字段 | 约定 |
| --- | --- |
| `key`、`label`、`value` | 稳定唯一键、字段名称、已确认内容 |
| `module` | `personal`、`education`、`internship`、`project`、`language` |
| `recordId`、`recordLabel`、`recordHint` | 经历标识、名称、区分提示 |
| `aliases` | 字段同义词；户籍、生源地、籍贯与现居地分别维护 |
| 根对象 `profiles` | 用户自己的版本定义 `[{id, label}]`；新资料默认只有 `general`（默认资料），稳定 ID 与显示名称分开 |
| 字段 `profiles` | 适用版本 ID 列表，必须引用根对象的版本定义；不内置求职方向 |
| `sensitive` | 填写计划隐藏完整值，资料库与确认填写时可查看 |
| `manual`、`companyScope` | 人工确认或公司专属资料，不自动泛化 |
| `precision` | `month` 或 `day`，不为年月资料补日期 |
| `ongoing`、`dateFallback` | 项目／实习结束日期为「至今」时可设 `ongoing: true`；经用户选择后设 `dateFallback: "today"`，仅对日期控件使用当天占位 |
| `gpaScale` | 已确认的满分口径，未知时留空 |

Agent 可使用打包资料工具的 `filling export`，或源码命令导出私人资料包；命令只导出，不修改母本：

```bash
python3 app/desktop_runtime.py filling --workspace /path/to/private-workspace export --output /path/to/private-profile.json
```

## 主观题草稿

**个人评价、优劣势、专业技能、兴趣爱好或求职动机可逐题交给 Agent 起草，由本人核对后填写。** 没有匹配资料的事实字段仍保留待补，不把未知身份、家庭信息或个人意愿交给模型猜测。

1. 识别招聘页面，在对应文本问题旁点击“根据我的资料回答此题”。
2. 点击生成，使用协作设置中自己选择的 Codex 模型；也可复制单题任务交给自己的 Agent，再导入其 JSON 结果。
3. 阅读可编辑的回答、所用经历和待确认事项。资料没有提供的兴趣、意愿和成果不可补造；内容不合适时修改或放弃。
4. 点击“采纳草稿，加入待选填写”，再勾选该字段并填写。已有内容需要明确同意覆盖；填写后检查网页读回结果。

**草稿只服务当前页面，不自动写回个人资料库。** 重新识别、切换资料版本或网页发生变化后需要重新核对。模型只接收当前版本经过筛选的经历内容，排除敏感标记、身份、联系方式和家庭字段。主动生成使用既有 Codex 额度，不需要 API Key；外部 Agent 的费用取决于用户自己的工具。

## 支持范围与开发

**可靠识别和读回是执行前提。** 原生输入框、文本域、日期、单选、下拉框、简单 ARIA 选择器、开放 Shadow DOM 和同源 iframe 可以处理。附件、验证码、协议、家庭成员和联系人保留人工操作。跨域 iframe、复杂级联和无语义控件需要适配；日期缺日、选项不唯一、GPA 口径不明或文本超长时不猜测或截断。

**Moka 申请表按字段标题、模块与教育记录识别。** 字段下的校验提示和当前选值不会再被当作标题。普通 Moka 下拉框在用户确认填写后展开，只选择当前控件菜单中唯一同名的选项，并读取实际选中显示值；没有选项或存在重名时保留原值。教育记录仅按页面已有的明确学历区分，不按顺序猜测。常见的四项年月范围按开始日期和结束日期识别，再从已确认资料拆出年份、月份，不把已有年份当作字段名称。空白记录同样识别；多段经历缺少区分依据时由用户选择，不按顺序猜测。Moka 日历、其他未明确结构的日期组合、锁定字段与复杂联动暂需人工处理，计划会显示具体原因。

合成验收不代表所有招聘网站已适配。真实网站需要分别检查识别覆盖、填写结果、网站保存与耗时，未实测不宣称优于第三方产品。

**扩展与桌面 App 分开构建，共用填写约束。** 本机工具只包含受限连接模块，只读写当前绑定工作区的固定填报资料。普通模型映射只收到标签和资料键；主动生成主观题时额外发送当前版本经过筛选的经历内容。连接工具不接受调用方的文件路径或任意命令。

```bash
python3 browser-tools/build.py --python /path/to/python-with-pyinstaller --output /path/to/browser-package
```

仅构建扩展可加 `--skip-helper`。固定扩展 ID 用于 Chrome Native Messaging；更新应替换原扩展文件后重新加载，以保留浏览器本地资料。不要移除扩展再安装。模型目录接口参考 [Codex App Server 文档](https://developers.openai.com/codex/app-server/)。

## Agent 核对反馈

**识别先展示本地计划，Agent 再核对歧义字段。** 弹窗保留本次核对的运行状态、所选模型、耗时和逐项结果：网页字段、对应资料、是否采纳及校验结果。返回零条匹配、调用失败、建议被约束拒绝会分别说明；关闭弹窗后重新打开仍可查看本次结果。核对期间修改匹配或重新识别，旧结果不会覆盖新计划。

**语义匹配选择已有资料，不生成填写事实。** 名称不完全相同的字段可由 Agent 根据标签、模块和经历提示对应到已有资料键；本地继续校验模块、记录与控件约束。同义学历选项按相同含义核对，Moka 下拉框只选择唯一等价选项。多段经历无法明确区分时保留待确认，已有内容不会自行覆盖。
