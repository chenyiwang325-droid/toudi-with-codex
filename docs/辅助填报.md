# Chrome 辅助填报

**辅助填报是 TouDi 投递中控台的浏览器扩展，在当前招聘网页识别、核对、填写和读回表单。** 中控台管理求职任务和正式填报资料；扩展执行当前网页操作。App、扩展与 Agent 共用工作区 `填报资料/资料.json`，扩展在未连接或离线时也可维护本地资料。

**本文对应当前源码；公开可下载版本以 [Release 附件](https://github.com/chenyiwang325-droid/toudi-with-codex/releases)为准。** 升级时同时更新扩展和浏览器连接工具：替换扩展目录后在 Chrome 扩展管理页点击“重新加载”，再运行包内连接安装程序。不移除扩展，不重新导入资料；扩展与表单引擎分别显示版本，只有界面调整时引擎版本可保持不变。旧计划需要重新识别。

## 安装与首次配置

**推荐先用 Codex 整理完整资料，再配置 Luna 核对当前表单。** 从 [Releases](https://github.com/chenyiwang325-droid/toudi-with-codex/releases) 下载 `TouDi-browser-macos-arm64.zip`；仅需要本地填写和复制时也可使用 `TouDi-filling-extension.zip`。App、扩展和 Codex 连接同一份正式资料，初始化步骤见[开始使用](开始与初始化.md)。

1. 解压工具包。在 Chrome 的 `chrome://extensions` 开启开发者模式，点击“加载未打包的扩展程序”（部分版本显示为“加载已解压的扩展程序”），选择 `TouDi-filling` 文件夹，并将插件固定到工具栏。
2. 要与 App 共享资料时，运行包中的“TouDi 浏览器连接”安装程序一次，在插件“资料与设置”中显式连接当前 TouDi 工作区。已有浏览器资料与工作区资料不一致时先核对双方，再选择保留或合并；不依赖模型登录。未连接也可先用标准表单填写，已有私人资料包可导入。
3. 打开“Agent 协作”，选择“本机 Codex”。安装官方 Codex 桌面客户端或 CLI，使用自己的 ChatGPT 账号登录，并确认已安装上一步的连接工具。
4. 点击“检查连接与模型”，从当前客户端返回的目录选择 **`gpt-6-luna`** 并保存。已保存的明确模型选择不会自动更换；Luna 不在目录中时先保留本地匹配，不转用 API 或其他模型。
5. 在招聘页点击 TouDi 图标，先查看识别结果，再按需点“Agent 核对”。返回完成状态和结构化决定后才算本次接通；然后点“自动填写”，检查网页最终值。

**Luna 是语义核对的推荐模型，核对仍由用户选择。** 程序先读取真实选项，再判断本地规则无法确定的非敏感字段；只更新可填写结果，不写入网页。点击“自动填写”才执行，明确日期和通用匹配优先用本地规则。核对不改写原文、不补造日期，模型不可用时保留本地计划，未完成项可从“我的资料”复制。

**核对进度和最终决定在浮窗中查看。** 运行时显示当前读取选项或核对的板块及板块序号；完成后展开“查看核对结果”，按板块查看网页字段、对应资料、最终填写文字或所选选项，以及已采用、未采用或未确定的状态。核对不会要求逐项批准。自动填写只处理可执行的对应内容，不再次展开没有匹配资料的选择器；已经读取的选项在当前页面和资料未变时复用，执行时仍以真实菜单及填写后的值读回为准。

| 协作方式 | 使用条件 | 日常操作与费用 |
| --- | --- | --- |
| 本地规则 | 已保存个人资料 | 先识别、再点击填写与核验，无模型费用 |
| 本机 Codex | 连接工具、官方客户端、ChatGPT 登录、已选模型 | 插件填写前核对对应资料与选项，使用现有 Codex 额度，无 API Key 或新增模型服务 |

**其他协作方式作为兼容入口保留。** 仅需本地识别、填写和复制时选择“暂不接入 Agent”；已有外部工具可选择“使用自己的 Agent”，复制任务并导入 JSON。推荐开始流程使用本机 Codex 与 Luna，外部工具不属于安装前提。

**“检查连接与模型”只读取登录状态和模型目录，不发起模型生成。** 工作区资料连接是独立操作，只通过本机工具读取当前绑定资料。 模型目录不保证账号本次可调用；实际核对成功才证明该次接通。模型不可用、超时或额度受限时保留本地计划。连接工具由 Chrome 按需启动，日常无需打开 TouDi App 或终端。

连接工具负责本机资料同步和所选模型调用；升级保留原绑定和资料。

当前发布验证 macOS Apple Silicon。安装包为临时签名，未进行正式公证；其他平台可阅读源码，尚未完成安装包与真实浏览器验证。

## 从中控台进入填报

**中控台左侧“扩展功能 → 辅助填报”提供填写资料、安装指南和扩展入口。** 已安装扩展时，点击“Chrome 连接与设置”直接在 Chrome 打开资料库；尚未安装时按入口中的指南操作。

在 App 的“填报资料”使用标准表单维护内容；扩展首次显式连接后共享同一母本。正式文件不存在时兼容读取根 `网申信息库.json`，首次保存建立 `填报资料/资料.json` 并保留旧文件。私人导出用于备份或离线交换，不再作为日常更新的必经步骤。Agent 通过公共 `profile` 管理入口读取版本、校验候选、提交和读回。

**扩展中的“打开投递中控台”用于返回已安装的 App。** 此入口通过本机连接工具打开固定 TouDi App，不依赖模型登录；尚未安装工具或 App 时，可查看旁边的安装与使用指南。网页填写不会自动提交申请或修改中控台投递状态，网站提交完成后再确认对应记录。

## 在网页中识别与复制

**点击 Chrome 工具栏的 TouDi 图标，先查看当前招聘页的识别结果。** 浮窗按模块列出可填写、已一致和未匹配字段，打开时不新增经历或写入网页。拖动顶部横条可以移动窗口；右上角分别用于最小化和关闭。窗口保持固定宽高，“自动填写”和“我的资料”切换时不改变外壳尺寸，较小屏幕仅按可用高度限制窗口。再次点击图标会重新打开窗口，并保留仍有效的填写计划。

**浮窗仅属于打开它的招聘网页。** 加载失败时在原位置点击“重新加载浮窗”，网页已填写内容保持原样。切到其他页面、跳转或关闭原页后，先回到需要填写的页面重新打开 TouDi。

- **自动填写**：先查看识别结果；需要语义判断时点击“Agent 核对”，结果更新后再点击“自动填写”。也可直接填写本地已匹配内容。执行中只保留进度和简短结果，不要求逐项选择或查看内部计划。外部 Agent 任务和主观回答位于“资料与设置 → Agent 协作 → 补充任务”。
- **我的资料**：不必先识别即可浏览。所有分类和经历放在同一个连续列表，可从上向下滚动到最后一项。左侧目录只定位到对应位置，滚动时标出当前分类；不隐藏其他资料，也不需要切换记录。个人信息按身份与学历、联系方式、地址与户籍、紧急联系人、技能与评价等分组；短字段并排，长正文独立呈现。经历统一区分名称、基本信息和详细内容；荣誉、奖学金与竞赛分别定位。搜索可跨分类查找。
- **复制原文**：点击字段内容即复制完整值，长文的省略只用于显示，可点击“展开全文”，不提供整段打包复制。

悬浮窗口绑定打开它的网页；切换页面后不能借原窗口操作另一个标签。资料界面位于扩展自己的隔离 iframe，招聘页只承载窗口外壳和位置，不接收个人资料消息。

## 填写自己的资料

**资料库预设通用字段和输入控件，具体内容由每个用户填写。** 首次打开只有一套“默认资料”，没有作者的个人信息、经历或求职方向。空白字段不参与自动填写，也不要求先编写 JSON。

| 模块 | 填写内容 | 操作方式 |
| --- | --- | --- |
| 个人信息 | 姓名、手机、邮箱、居住地、性别、出生日期；证件、最高学历和个人评价等按需补充 | 填写一次，之后直接编辑 |
| 家庭成员 | 姓名、关系、工作单位、职务、联系方式等按实际要求填写 | 每位成员独立添加，仅在本机匹配 |
| 教育经历 | 学校、学历、专业、学位、起止日期；学院、学习形式、GPA 和课程等选填 | 按学校／阶段逐段添加 |
| 工作与实习 | 单位、岗位、部门、地点、起止日期、工作职责；工作类型与成果选填 | 每段经历单独添加和编辑 |
| 项目经历 | 项目名称、角色、日期、描述、本人职责；成果与链接选填 | 每个项目独立管理 |
| 语言能力 | 语言／证书名称、熟练程度、成绩；取得日期选填 | 可以添加多种语言或证书 |
| 在校经历 | 组织名称、职务、起止日期、职责描述；成果选填 | 每段校园任职或学生工作独立管理 |
| 荣誉获奖 | 奖项名称、获奖级别、奖项等级、类别、日期、颁奖单位；完整获奖说明选填 | 每项真实奖项独立管理 |
| 论文发表 | 论文名称、刊物、发表日期、作者排序；摘要和链接选填 | 每篇论文独立管理，不推测发表或作者位次 |

1. 使用各模块的“填写”或“添加”按钮，完成一份资料或一段经历。文字内容直接填写，学历等常用选项直接选择；选项不适用时选择“其他（自行填写）”。
2. 日期选择“年月”或“具体日期”，按实际信息填写；工作、项目和在校经历尚未结束时勾选“仍在进行”。程序不为只有年月的资料补造具体日。
3. 在板块编辑表单的“字段与匹配设置”中添加自定义字段，模块与经历自动带入。已有补充字段直接在同一表单修改；查看单项匹配设置时保留整段尚未保存的内容。
4. 左侧目录定位模块，标题旁的“编辑板块”在原位置打开整段表单，无需先展开记录，也不会弹出另一窗口。个人信息、技能和自我评价统一编辑；工作、项目等仍按独立经历编辑。保存后回到招聘网页重新识别。

**点击字段内容即可复制完整值。** 简短字段成对排列，长文默认显示前三行，可展开全文；省略只用于浏览。旧资料中标记为仅供参考的简版、完整版等原文放在“补充参考”中，默认折叠；它们不与正式字段竞争自动匹配，也不改变已经确认的正式内容。

**App 内打开的资料表单自动接收工作区更新。** 正在编辑时保留原内容和保存版本；其他工作区资料继续更新，结束编辑后自动接收新资料，发生冲突时保留编辑并提示核对。

**资料库保存用户提供的完整原文。** 浏览页的省略仅影响显示，点击复制、打开编辑表单、保存和自动填报均使用完整值；不自动生成简述、缩写或替换用户内容。

**一套资料即可开始使用，多个版本仅在需要不同简历内容时建立。** “管理版本”支持自行命名、复制当前版本和删除不再使用的版本；复制产生独立资料，修改副本不会改动原版。导入包已有的版本名称与字段归属按原数据保留，不用作者的求职方向替代用户设置。导入资料存在共享字段时，编辑窗口会说明其影响范围。

## 在招聘网页填写

**网页先自动识别，Agent 核对可选，填写单独执行。** 核对或填写期间可以切换“我的资料”查找和复制。

1. 在招聘网页点击 TouDi，选择本次资料版本，查看按模块组织的识别结果。默认填写全部内容；需要保留网页现值时选择“仅填空白”。
2. 如需处理歧义，点击“Agent 核对”。程序对照当前字段、实际选项与对应资料，返回可执行的字段和选项决定；完成后刷新可填写结果，不写入网页。
3. 点击“自动填写”。先填写已有明确归属的记录，等待联动更新并重新识别，再逐段新增和填写剩余经历。每轮按身份字段、当前节点与已读回的内容重新对应记录；读取真实选项，并按完整资料原文写入。日期与通用选项由本地规则处理；仍然有效的核对结果可直接沿用，填写不再次调用模型。
4. 等待简短结果。每次写入和本轮结束都读回核验；未完成项说明具体原因及下一步，点击字段名称即可到“我的资料”检索复制。同一个失败控件在条件未变化时，本轮不重复打开。
5. 在招聘网页检查内容，再由用户保存或提交。插件不点击网站保存、提交、上传、验证码或协议。

**页面联动可以续填，页面切换必须重新识别。** 同一表单新出现的字段重新使用当前资料匹配；已有字段仅在身份与控件约束仍可确认时重定位，不能沿用失效 ID。网页切换、资料版本改变、记录无法确认或页面持续变化时停止，保留已经写入的内容。重复点击共用同一任务；再次填写会重新识别现值，已一致的内容不重复改写，也不重复新增经历。原文不因网站字数限制被截断或替换成短稿。

**已保存卡片先打开编辑，不把它当作空白经历。** 当前可识别的编辑卡片或锁定记录会阻止盲目新增；用户在网页打开对应编辑区后可再次运行。网站要求先保存当前记录才能新增时，会在新增未生成新记录后停止并提示。填写器不代点网站“保存”“下一步”或“提交”，也不把输入框读回成功称为网站已保存。

## 平台识别与控件操作

**同一套资料用于多个网站，平台适配处理不同的表单结构和控件。** 当前包含通用表单、Moka、Zhiye / Phoenix 与 Ant Design 表单适配器。适配按实际组件结构识别，规则不依赖某家公司或个人资料。字段标题与已有填写值分开读取，重复经历保持独立分组；Agent 核对含义不明确的字段与实际选项。

| 控件 | 操作与核验 |
| --- | --- |
| 原生日期、单选和下拉 | 检查格式、选项及限制，填写后读回 |
| Moka 普通下拉、拆分年月 | 展开对应字段菜单，选择唯一等价选项；年月取自已确认的起止日期 |
| Phoenix 自定义单选 | 对应唯一选项，检查禁用状态，再读回选中项 |
| Phoenix 搜索下拉 | 只操作刚打开的菜单，查找唯一选项并点击“确定”，核对保留值 |
| Phoenix 地区选择 | 搜索地区，通过选择图标选中，点击“确定”；同名不唯一时转人工 |
| Phoenix 日期 | 按实际月历或日历选择年、月、日并读回；只有年月时不补造具体日 |
| Ant 单选与下拉 | 读取表单项标题；单选使用该组自己的选项，下拉只操作由当前控件关联的菜单，选择唯一等价项后读回 |
| Ant 拆分年月与省市 | 将同一问题内的两个选择框合为一个字段，按资料依次选择；省市取自完整来源地区，不补造上级行政区 |
| Ant 日历输入 | 打开已适配的日历弹层，在日历输入框填写完整日期并确认，核对表单显示值；其他日历结构仍需适配 |

**个人信息中的学历摘要与完整教育经历共用资料。** “最高学历毕业院校、毕业时间、学习形式”等字段采用明确最高学历对应的教育记录；“第一学历”按已确认的高等教育起始时间确定，高中履历可独立填写，不替代本科或专科记录。英语等级证书与成绩采用同一条已通过的四级或六级记录。记录不唯一或依据缺失时保留待确认，不混用不同学历、证书的字段。

**结构辅助先提供候选，再接受 Agent 的选择。** 无法可靠确定标题或分组时，引擎仅提取附近的标题候选，Agent 返回候选 ID，本地验证后重新生成计划。已通过校验的结构规则按网站、路径、引擎版本和结构指纹复用；页面结构变化后失效。不接收生成的脚本、选择器或个人事实，未识别的复杂控件不会因 Agent 建议而强行执行。

**结构辅助和资料核对分别显示进度与结果。** 用户选择 Agent 核对后，先完成必要的结构辅助，再按板块核对资料歧义；本地计划先显示，模型调用不阻塞资料查阅。也可复制结构任务给自己的 Agent 后导入结果。执行期间若用户改动匹配、清除计划或页面值变化，旧结果不再采用。

多选集合、任意级联、未明确结构的日历、附件和网站提交仍需人工操作或进一步适配。默认填写全部可匹配内容；选择“仅填空白”可保留网页现值。读回失败会报告失败，不视为网站已保存。

## 资料保存与更新

**正式工作区为共享母本，Chrome 保存可离线使用的副本。** 首次点击连接后，扩展在读取、保存与识别时同步并读回；用户可主动重新同步或断开。App、扩展与 Agent 的已同步修改进入 `填报资料/资料.json`，不使用 Chrome 云同步，也不宣称完整云端同步。

离线或连接失败时，修改留在 Chrome 并显示待同步；恢复连接后核对双方版本。无冲突变更可合并，同一字段修改不同或工作区变更时保留双方，先审阅再选择；不会通过替换基准静默覆盖。卸载或迁移扩展前导出私人备份。App 完整备份不包含 Chrome 尚未同步的修改，不能据此清除浏览器副本。

**手动复制不需要先识别网页。** 在悬浮窗选择本次资料版本，切换“我的资料”标签，再按目录或搜索找到所需内容。浏览器副本立即显示，工作区同步在后台核对；连接延迟不会把整个资料窗口锁在空白加载状态。点击单项直接复制完整字段内容，可粘贴到未适配的控件；资料与设置页也提供复制入口。切换版本后重新读取对应资料，避免混用其他版本。身份与联系方式可由本人查阅和主动复制；复制内容不会自动发给模型或写入网页。

插件支持分模块查阅、搜索、整段经历与补充字段的新增／编辑／删除，以及按需维护别名、适用版本、日期精度、GPA 满分、人工确认和填写规则。保存检查资料版本，更新后旧计划失效。

**经历按开始时间倒序查阅，稳定标识与简历口径保持一致。** 教育、实习、项目和在校经历按开始日期排序，获奖和论文分别按获奖、发表日期排序；缺少可靠日期的记录排在后面，彼此保留原序。展示顺序不会让 Agent 自动猜测网站中没有名称的经历卡片。

**进行中的经历保存「至今」，具体日期只是已授权的表单占位。** 项目或实习的结束日期可设置 `ongoing: true`。网站支持「至今」的文字或等价下拉选项时直接使用；只有必须填写日期、且用户已选择 `dateFallback: "today"` 时，才使用填写当天。计划会说明占位性质，母本继续保存「至今」；日期超出网站限制时转人工核对。同一经历的结束时间提供唯一「至今」勾选时，直接勾选并读回；不操作其他复选框。

**不同经历和资料版本必须有明确归属。** 网页已有非空记录不能按顺序猜测本科、硕士或实习；已有证据不足时保留待核对。空白和新建板块则是明确的填写目标，程序把当前版本中尚未出现的记录逐段安排到这些目标中，并让整段字段共用同一条资料。版本名称由用户决定，切换版本不会沿用其他版本的安排。

自然语言规则供自己的 Agent 核对。日期、记录归属、GPA、选项与已有值保护由程序检查；其他文字要求不能直接视为已经自动执行。

## Agent 接入与资料结构

**资料核对返回已有资料键和可验证的选项建议，最终填写值由浏览器本地取值。** 任务只包含当前待核字段标签、分组、真实选项及相关非敏感候选事实，不发送整库或网页其他现值。网页文字作为不可信数据，本机 Codex 的 shell、浏览器、应用和插件工具关闭。

返回格式为纯 JSON 对象：`{"fieldId":"factKey"}`。插件再次检查模块、语义、经历、日期和选项，模型映射不能绕过约束。字段修正仅在实际填写并读回通过后记住；下次按网站路径、引擎、资料版本、字段语义和记录归属重新校验。选项决定还要求刚读到的完整选项集合一致；不把未执行的建议或失败结果记成成功解法。最近核验只保存状态元信息，不持久保存实际填写值和 URL 查询凭据。

**模型任务和核对结果不累积为本机历史。** 本机 Codex 使用 `--ephemeral`；任务约束和答案文件位于临时目录，在成功、失败、超时或无效返回后清理。扩展把当前计划、选项和核对结果放在 Chrome 会话存储中，只保留一份；关闭对应招聘标签页时删除，更换网页或资料后失效，计划十分钟未更新后在下次读取时清理。最近一次填写报告覆盖上一份，只保存字段 ID、模块、控件类型、执行阶段、原因代码与状态，不保存资料值或模型原始回答。正式资料、读回通过的字段对应关系及受限的结构规则属于可复用配置，继续保留；复用元信息不包含资料原文或整份网页选项。

**资料包包含已确认事实、经历关系和适用条件。** 根对象为 `schemaVersion: 1`，包含 `facts`、`rules`，以及 `profiles` 版本定义和可选的 `savedAt`、`name`、`supplements`。不提供作者资料或示例经历。

| 字段 | 约定 |
| --- | --- |
| `key`、`label`、`value` | 稳定唯一键、字段名称、已确认内容 |
| `module` | `personal`、`family`、`education`、`internship`、`project`、`language`、`campus-role`、`awards`、`publications` |
| `recordId`、`recordLabel`、`recordHint` | 经历标识、名称、区分提示 |
| `aliases` | 字段同义词；户籍、生源地、籍贯与现居地分别维护 |
| 根对象 `profiles` | 用户自己的版本定义 `[{id, label}]`；新资料默认只有 `general`（默认资料），稳定 ID 与显示名称分开 |
| 字段 `profiles` | 适用版本 ID 列表，必须引用根对象的版本定义；不内置求职方向 |
| `sensitive` | 填写计划隐藏完整值，资料库与确认填写时可查看 |
| `manual`、`companyScope` | 人工确认或公司专属资料，不自动泛化 |
| `precision` | `month` 或 `day`，不为年月资料补日期 |
| `ongoing`、`dateFallback` | 项目／实习结束日期为「至今」时可设 `ongoing: true`；经用户选择后设 `dateFallback: "today"`，仅对日期控件使用当天占位 |
| `gpaScale` | 已确认的满分口径，未知时留空 |

Agent 可使用打包资料工具的 `filling export`，或源码命令导出私人资料包；命令只导出，不修改母本：

```bash
python3 app/desktop_runtime.py filling --workspace /path/to/private-workspace export --output /path/to/private-profile.json
```

## 主观题草稿

**个人评价、优劣势、专业技能、兴趣爱好或求职动机可逐题交给 Agent 起草，由本人核对后填写。** 没有匹配资料的事实字段仍保留待补，不把未知身份、家庭信息或个人意愿交给模型猜测。

1. 在招聘网页打开 TouDi 完成识别，再打开“资料与设置 → Agent 协作 → 补充任务”，点击“读取当前网页任务”并选择网页问题。
2. 点击生成，使用协作设置中自己选择的 Codex 模型；也可复制单题任务交给自己的 Agent，再导入其 JSON 结果。
3. 阅读并编辑回答草稿。资料没有提供的兴趣、意愿和成果不可补造；内容不合适时修改或放弃。
4. 点击“采纳并填入当前网页”，仅把这道题的回答填入原招聘页并读回，不改写个人资料库。

**草稿只服务当前页面，不自动写回个人资料库。** 重新识别、切换资料版本或网页发生变化后需要重新核对。模型只接收当前版本经过筛选的经历内容，排除敏感标记、身份、联系方式和家庭字段。主动生成使用既有 Codex 额度，不需要 API Key；外部 Agent 的费用取决于用户自己的工具。

## 支持范围与开发

**可靠识别和读回是执行前提。** 原生输入框、文本域、日期、单选、下拉框、简单 ARIA 选择器、开放 Shadow DOM 和同源 iframe 可以处理。附件、验证码与协议保留人工操作。已保存的紧急联系人、家庭成员及实习证明人普通文本字段可在本机匹配填写；不同人员保持独立记录，相关资料不发送给模型。跨域 iframe、复杂级联和无语义控件需要适配；日期缺日、选项不唯一、GPA 口径不明或文本超长时不猜测或截断。

**Moka 申请表按字段标题、模块与教育记录识别。** 字段下的校验提示和当前选值不会再被当作标题。普通 Moka 下拉框在用户确认填写后展开，只选择当前控件菜单中唯一同名的选项，并读取实际选中显示值；没有选项或存在重名时保留原值。教育记录仅按页面已有的明确学历区分，不按顺序猜测。常见的四项年月范围按开始日期和结束日期识别，再从已确认资料拆出年份、月份，不把已有年份当作字段名称。空白记录同样识别并自动安排资料；点击自动填写后通过明确的新增入口补齐段数。已有非空经历缺少区分依据时保留待核对，不按顺序猜测。Moka 日历、其他未明确结构的日期组合、锁定字段与复杂联动暂需人工处理，计划会显示具体原因。

合成验收不代表所有招聘网站已适配。真实网站需要分别检查识别覆盖、填写结果、网站保存与耗时，未实测不宣称优于第三方产品。

**扩展与桌面 App 分开构建，共用填写约束。** 本机工具只包含受限连接模块，只读写当前绑定工作区的固定填报资料。模型核对收到当前字段的标签、实际选项及对应候选的非敏感事实值；主动生成主观题时额外发送当前版本经过筛选的经历内容。连接工具不接受调用方的文件路径或任意命令。

```bash
python3 browser-tools/build.py --python /path/to/python-with-pyinstaller --output /path/to/browser-package
```

仅构建扩展可加 `--skip-helper`。固定扩展 ID 用于 Chrome Native Messaging；更新应替换原扩展文件后重新加载，以保留浏览器本地资料。不要移除扩展再安装。模型目录接口参考 [Codex App Server 文档](https://developers.openai.com/codex/app-server/)。

## Agent 核对

**Agent 核对先返回可填写决定，由用户点击填写。** 使用模型前先读取当前字段的真实选项，即使初次没有匹配到资料，也会检查已适配的下拉控件。模型返回既有资料键；选择题同时返回网站实际提供的选项值，不能用解释或空选项代替决定。不确定的字段保留未匹配。结果通过本地字段与记录约束后更新列表；调用失败时保留本地已确认的计划。页面、资料、对应关系或选项变化后，失效决定不继续写入。

**语义匹配选择已有资料，不生成填写事实。** 名称不完全相同的字段可由 Agent 根据标签、模块和经历提示对应到已有资料键；本地继续校验模块、记录与控件约束。同义学历选项按相同含义核对，Moka 下拉框只选择唯一等价选项。多段经历无法明确区分时保留待确认，已有内容不会自行覆盖。

开发接入的模块标识为 `campus-role`、`awards`、`publications`，对应在校经历、荣誉获奖、论文发表；它们与 `personal`、`education`、`internship`、`project`、`language` 共用原 `schemaVersion: 1` 的事实结构。每段资料保留独立 `recordId`、稳定 `key` 和 `profiles` 归属。新模块不会自动借用实习或项目中的同名字段，已有非空记录没有明确区分依据时保留待核对；空白和新建记录按当前版本自动安排。主观问答只能引用已保存的奖项与论文事实，不能推断荣誉、发表状态或作者位次。

## 选项语义核对

**本机 Codex 核对会对照字段问题、网站实际选项与对应经历事实作判断。** 例如本人是第五作者，而网站只提供第一作者、通讯作者、其他时，可以建议“其他”；作者姓名列表用于作者名单字段，不能作为本人排序。选项与网页文字只作数据，不作为 Agent 指令。资料为未知或未核实的收录类别不作肯定判断，SCI、SSCI 等类别不能自行互换。

**菜单未展开时，先读取当前字段自己的选项，再核对。** 已适配的 Phoenix、Moka 与 Ant 平面下拉会短暂展开并关闭，不选择条目或保存表单；地区树、多选、无法关联的菜单保留人工处理。没有取得真实选项时不生成选项值，仍可使用分类资料复制。

**每条建议带资料键、所选候选与理由，填写前仍由本地规则校验。** 不允许跨经历、生成新值或返回候选之外的选项；填写时再次检查控件和已有值并读回。建议仅对当前页面计划有效，不把网站选项永久记为个人事实。论文资料可以分别保存作者排序、作者名单、发表状态、收录类别、在线发表日期、正式出版日期和卷期页码。

**长文资料可以仅供复制和主动问答引用。** `manual: true` 仍禁止普通字段自动填入；核实完成且明确允许生成问答引用的素材可同时设置 `answerSource: true`。未授权的旧人工材料及冲突版本不进入问答来源。该许可不放开敏感字段、身份、联系方式或家庭信息；问答仍需用户采纳后才能填入。

**填写使用资料中已确认的完整正文。** 不按网页 `maxlength` 预先拒绝、截断或切换短稿；内容适配由用户交给自己的 Agent 执行。实际填入后仍逐字读回并报告网站本身的校验结果，不把网站截断或拒绝当成成功。模型字段候选按规范模块建立，“最高学历/最高学位”和最高学历的毕业日期分别采用明确的个人/教育语义归属，不与“专业人数”等其他问题混用。

### 按整段经历核对

家庭成员、语言证书、教育、工作、项目、校园、获奖和论文按“模块 → 具体记录 → 字段”匹配。已有学校、公司、项目名称等足以唯一识别时，整段沿用同一记录；空白板块自动安排当前版本尚未出现的记录，不要求逐段选择。已有非空经历的信息冲突时，可纠正对应关系；网页顺序不作为已有经历的身份依据。

同一段的字段候选限定在绑定记录内。资料有几段，默认就准备几段；点击“自动填写”后才操作网站新增入口，再重新扫描新板块并填写。新增使网站整页重新渲染或改变字段位置时，按记录节点与原内容重新对应，不能沿用失效的字段 ID。已出现的记录不重复新增，网站数量上限或无效入口留下具体报告。更换某段记录会清除该段旧的单字段匹配，其他段保留；未绑定的非空经历不交给模型猜测所属经历。

CLI 核对支持 `plan --record-bindings <JSON文件>`，文件内容是当前扫描的 `groupId` 到资料 `recordId` 的映射，与插件整段选择使用同一约束。
