# 编辑与保存

**桌面 App 与 Agent 使用同一个正式工作区，保存由公共资料管理组件执行。** 工作区位于安装目录外；缓存和静态查阅版不作为母本。公司准备保留 Markdown 母本与派生 JSON，探查保留目录、正文和引用附件。

## 当前功能核对

**业务管理按模块提供入口，导入必须符合现有内容契约。** 任意招聘网页、PDF 或录音并不是可直接导入的规范业务数据；由用户或 Agent 先整理为约定 JSON/Markdown。

| 内容 | 管理能力 | 正式保存位置 |
| --- | --- | --- |
| 投递记录 | 新增、字段编辑、规范 JSON 导入/导出、删除；保持标记关联 | `投递数据/投递记录.json` |
| 标记与求职偏好 | 进度、收藏、适合与否、待查、备注、偏好 | `投递数据/用户编辑数据.json` |
| 通用准备 | 分类与条目管理，规范 JSON 导入/导出 | `投递数据/逐字稿数据.json` |
| 公司准备 | 公司与岗位表单建立标准标题和空章节；编辑 Markdown、规范导入、导出、删除 | `面试准备/` 与派生 `投递数据/面试准备数据.json` |
| 岗位探查 | 报告管理、规范导入/导出与附件引用 | `岗位探查/` 及 `探查目录.json` |
| 面试复盘 | 场次与问答管理、Markdown/规范数据导入、导出、删除 | `复盘/` 与 `投递数据/面试复盘数据.json` |
| 填报资料 | 通用字段与整段经历表单、资料版本、填写要求、规范导入/导出；扩展连接后共享 | `填报资料/资料.json` |
| 工作台配置与草稿 | 工作区配置与草稿持久保存 | `投递数据/工作区配置.json`、`草稿数据.json` |
| 完整备份 | 导出 ZIP、恢复检查与版本保护 | 用户选择的备份文件；事务恢复副本留在工作区 |

**API 与 CLI 共用同一管理实现。** `GET /api/manage?module=…` 返回 `{version,data}`；模块包括 `records`、`edits`、`qbank`、`preps`、`prospects`、`reviews`、`profile`、`settings`、`drafts`、`workspace`、`trash`。投递返回关联键 `keys`，准备和探查读取时带正文。提交使用 `POST /api/manage`；公司准备与探查通过带 Markdown 的条目提交，一并维护母本和索引。预览发送 `dryRun: true`，执行真实格式与版本校验但不保存。普通通用准备使用分类/条目表单，JSON 仅作高级批量导入。详细命令见[Agent 接入](Agent接入.md)。

## 统一保存规则

**以持久写入成功并读回为正式保存完成。** 输入变化与预览并不等于已保存；失败应保留候选与草稿。

1. 读取最新资料与对应模块返回的版本，保留稳定身份、来源、关联与无关内容。
2. 配置与草稿分别原子保存，不生成事务历史；公共业务组件校验格式、路径和引用，在同一资料锁内执行受保护事务；准备 Markdown 与派生 JSON 一致提交。
3. 保存返回新版本后读回，核对本次目标、个人标记、正文与附件。
4. 版本冲突保留候选，读取最新差异后重新合并；不能仅换 `base` 覆盖。
5. 删除与恢复使用受保护事务，恢复前核对变更范围；恢复副本可能涉及关联文件。
6. 完整备份校验清单、路径、哈希与格式，恢复前导出当前备份，恢复后核对各模块。

**旧接口与新管理接口的版本不可混用。** 旧标记/题库/复盘接口仍使用各自返回的版本，新管理接口与 CLI 的业务模块共用业务版本，`profile` 使用正式填报文件版本（首次兼容时包含旧源基准），`settings/drafts` 各自独立版本，`workspace/trash/完整恢复` 使用全区版本；原文件发布命令使用 SHA256。始终使用同一次读取所对应的入口提交。

## 静态查阅版

**静态网页只读取已发布的加密快照。** 业务编辑被关闭，显示设置可留在当前浏览器；换设备或清除浏览器数据不会改变桌面正式资料。需要更新查阅版时从一致母本重新构建并发布。网页管理增强需要另行提供可写后端与同步规则。

## 验证边界

**支持范围以当前 Release 的实际验收说明为准。** API 检查、源码测试、桌面 WebView 检查和安装包实机测试是不同证据；Windows CI 产物生成后仍需 Windows 实机验证，不能因构建成功便推断所有平台的安装、保存与恢复均已验收。
