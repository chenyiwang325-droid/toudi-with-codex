# 编辑与保存

**完整管理、用户配置与可靠保存是工作台的基本要求。** Agent 协作和手动操作应读取、修改同一份正式资料。加密阅读站是附加查阅入口，不能代替可写工作台；降低托管费用时保留这一功能要求。

## 静态部署能保存什么

**静态网页可以把设置保存在当前浏览器，但不能直接改写托管文件。** `localStorage` 按网站来源保存数据，可跨浏览器会话保留；换设备、换浏览器或清除站点数据后，不会自动带上原配置。它可以用于显示偏好与草稿，不作为跨设备和 Agent 共用的业务母本。[浏览器存储说明](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage)

当前加密快照明确为只读，业务修改被禁用。其主题、密度等浏览器设置能在当前浏览器保存，但投递、准备、探查和复盘不能写回网站或 Agent 工作区。把源代码直接上传为静态站，也不会产生服务端保存接口。

**静态前端配合可写 API 和持久存储，才能提供完整在线管理。** 前端负责编辑界面，API 验证并提交修改，存储保存正式资料；重新打开或更换设备从服务读取。Cloudflare Workers 与 D1 是计划中的同平台实现，当前尚未实现该适配。[D1 官方介绍](https://developers.cloudflare.com/d1/)

## 当前功能核对

**现有 Python 数据服务支持部分网页编辑和持久保存，所有模块的完整网页管理仍有缺口。** 下表区分实际实现与待补能力；文件导入和 Agent 同步是已保留的操作入口，不代表相应模块已有网页编辑器。

| --- | --- | --- | --- |
| 进度、收藏、适合与否、待查、备注 | 可修改与批量操作 | 工作区 `用户编辑数据.json` | 沿用版本保存保护。 |
| 求职偏好：性质、行业、学历 | 可配置 | 同一工作区文件的 `pref` | 在所有可写部署方式一致读取与保存。 |

## 统一保存规则

**完整版本的正式保存以持久存储提交成功为准，界面立即变化只代表草稿。** 用户操作与 Agent 更新按以下规则实现和验收；当前已经验证的范围列在下一节。

1. 加载最新资料和版本，提交只改本次目标；保留原身份、关联、来源与无关内容。
2. API 验证格式和引用，在同一事务或受保护批次中写入，成功后返回新版本。
3. 页面在确认成功后显示“已保存”；网络失败、限额或格式错误保留草稿并说明未提交。
4. 并发版本变化保留双方内容并提示对账，不以重新加载或换版本号强行覆盖。
5. 刷新、重新登录、服务重启和独立浏览器读取同样的业务资料；Agent 随后读取到网页修改。
6. 导入检查范围与身份，导出包含明确说明的内容，恢复前备份并核对关联；删除可恢复。

求职偏好、用户信源与共享配置属于正式工作区。主题等可以另保留本设备显示覆盖，但必须标明范围；配置恢复不能覆盖业务正文。访问密码和 Agent 凭据使用平台 Secret 或受控环境，不进入业务导出。

## 当前验证与完成条件

**现有保存能力已用隔离实例验证，完整网页管理尚未完成。** 检查覆盖投递标记与求职偏好、通用准备和复盘通过 API 写入，拒绝旧版本覆盖，Agent 读取网页修改，以及服务重启后新会话重新读取。此验证不等于 Cloudflare 适配或全部网页编辑入口已完成，也不等于真实托管网络性能已验收。

项目的完整在线版本需满足：上表业务模块具备对应编辑与导入入口；用户配置有明确保存范围；刷新、换设备及 Agent 均读取同一份正式资料；附件、关联、备份恢复和冲突保护可用。Cloudflare 免费适配需在这些条件下验证实际额度，不能通过改成只读达成费用目标。
