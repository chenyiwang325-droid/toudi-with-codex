# 备份与迁移

**完整备份包含正式业务资料、引用附件、工作区配置与草稿，使用带文件校验清单的 ZIP。** 局部的标记/偏好导出不能替代完整备份；备份同样包含私人资料，应保存到自己控制的位置。

## 导出与恢复

**在工作台导出完整备份，或用 App 提供的资料工具执行 `backup`。** 源码命令见[Agent 接入](Agent接入.md)。备份按受限业务资料清单生成，不包含访问凭据、源码、静态密文发布产物与事务历史。

**恢复先检查文件清单，再使用当前工作区版本确认提交。** 检查包含路径、哈希、规范 JSON、正文与引用附件；损坏或不完整的包不应当空库导入。恢复会替换备份覆盖的正式资料范围，先导出当前完整备份，保留恢复前副本。

**恢复后核对资料数量、身份、关联与正文。** 检查投递与标记、通用分类和条目、公司准备、探查正文与附件、复盘场次及配置；退出重开后再确认读取同一工作区。事务恢复副本位于 `投递数据/.transactions`，不是完整备份 ZIP 的内容。

## 迁移已有资料

**先从旧工作区生成完整规范资料，再迁入桌面工作区。** 旧系统的 HTML 内嵌数组或散落文件不能直接视为经过校验的备份。由用户或 Agent 核对记录字段、稳定 id、标记、Markdown 母本、派生内容及引用路径，再导入规范 JSON/Markdown 或生成备份包恢复。

1. 暂停旧目录写入，保留完整旧资料副本。
2. 读取最新材料，整理为现有内容契约；未知身份、日期和来源保留待核。
3. 在独立工作区先验证候选，核对附件和关联，再导入桌面正式工作区。
4. 打开 App 核对并重开验证；确认后指定新工作区为唯一母本，旧目录用于回退。

**迁移不自动改写用户原有脚本或云端实例。** 原工具仍写旧目录时须明确切换；在线模式先拉取最新版本，遵守自身同步规则。不能让两个目录继续独立写入再互相覆盖。

## 应用升级

**应用文件与用户资料分开，升级前仍应保留独立备份。** 从[桌面 Release](https://github.com/chenyiwang325-droid/toudi-workbench/releases/tag/v0.2.0)核对平台和版本后更新 App，不删除资料目录。当前公开 macOS 测试包采用临时签名、未公证；自动更新和正式公证以实际版本说明为准。
