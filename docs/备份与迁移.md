# 备份与迁移

**完整备份包含正式业务资料、引用附件、工作区配置与草稿，使用带文件校验清单的 ZIP。** 局部的标记/偏好导出不能替代完整备份；备份同样包含私人资料，应保存到自己控制的位置。

## 导出与恢复

**在工作台导出完整备份，或用 App 提供的资料工具执行 `backup`。** 源码命令见[Agent 接入](Agent接入.md)。备份按受限业务资料清单生成，不包含访问凭据、源码、静态密文发布产物与事务历史。

**恢复先检查文件清单，再使用当前工作区版本确认提交。** 检查包含路径、哈希、规范 JSON、正文与引用附件；损坏或不完整的包不应当空库导入。恢复会替换备份覆盖的正式资料范围，先导出当前完整备份，保留恢复前副本。

**恢复后核对资料数量、身份、关联与正文。** 检查投递与标记、通用分类和条目、公司准备、探查正文与附件、复盘场次及配置；退出重开后再确认读取同一工作区。事务恢复副本位于 `投递数据/.transactions`，不是完整备份 ZIP 的内容。

## 原地接入已有工作区

**已有工作区优先原地接入，保留文档、附件和用户编辑。** 不要求搬迁全部材料，不重建通用题库，也不重新导入已经在网页编辑过的复盘。旧格式仅做必要兼容：原 HTML 内嵌记录转为 `投递数据/投递记录.json`；重复条目 id 修正时保留内容和映射。

1. 暂停原流程写入，执行 `workspace adopt PATH` 查看预览和待修项。
2. 核对现有母本、数量、身份、标记、正文与引用附件，保留转换前完整备份及基准。
3. 仅确认本次兼容变更后执行 `workspace adopt PATH --apply --base PREVIEW_BASE`；基准变化时重新预览，不用旧候选覆盖。
4. 执行 `workspace check PATH` 校验，再 `workspace bind PATH`，或在 App 选择验证过的目录。
5. 在 App 核对各模块并退出重开；源码浏览器和 Agent 同样读取该目录。

**采用后投递记录以规范 JSON 为母本。** 采用事务在配置中登记 `recordsAuthority`（版本、规范文件和原 HTML 哈希），后续 App 编辑只更新 `投递数据/投递记录.json`；旧 HTML 内嵌记录可以滞后，不能反向覆盖。规范文件缺失时停止读取并核对备份，不自动回灌旧数据。

**已有信源处理链继续工作，只调整最终保存衔接。** 保留日期核验、主体归并、身份迁移、数据锁、版本和附件检查；公共项目不内置作者的飞书抓取链。旧脚本仍写另一目录时先明确切换，不能两处继续独立写入。

**备份恢复适合更换设备或目录，原地接入不要求恢复到新位置。** 需要迁移时，先校验完整备份，在目标独立工作区恢复并对账，再绑定。旧目录留作回退；不要同时把旧、新目录当成正式母本。

## 设置中的三个恢复相关操作

**日常修改自动保存，不需要每次导出。** “保存备份文件”用于换机或重要改动前保存全部资料，文件格式为 ZIP，可由 TouDi 恢复，不能作为网站直接打开。“选择备份文件”用于整体迁移或回退；确认界面先展示范围，再替换业务资料与设置。“查看历史修改”用于撤销误删或错误编辑，按修改时间和涉及模块选择副本。

**历史恢复的单位是所选修改涉及的完整文件。** 它可能覆盖这些文件中更晚的改动，确认前必须核对范围；当前内容会自动保留副本。未保存的编辑在对应模块出现“继续未保存编辑”，不另设通用管理草稿页面。

**草稿只属于产生它的工作区。** 当前版本按工作区隔离未提交编辑与待保存设置，保存成功后同步清除草稿镜像。早期没有归属标识的草稿保留为恢复依据，不自动恢复到当前资料；需要核对时导出未保存草稿或让自己的 Agent 查看工作区草稿文件，不通过旧缓存覆盖母本。

## 应用升级

**应用文件与用户资料分开，升级前仍应保留独立备份。** 从[桌面 Release](https://github.com/chenyiwang325-droid/toudi-workbench/releases/tag/v0.3.8)核对平台和版本后更新 App，不删除资料目录。当前公开 macOS 测试包采用临时签名、未公证；自动更新和正式公证以实际版本说明为准。
