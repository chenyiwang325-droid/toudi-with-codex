# 开始与初始化

**TouDi 推荐先由自己的 Agent 初始化，再按任务协作维护。** 你提供招聘信源、个人材料和使用要求；Agent 整理字段、分类与更新流程，App 负责查阅、手动编辑和保存。项目不预设作者的招聘来源、行业偏好或学历资格。

## 1. 打开 App，确定资料工作区

**从 [GitHub Releases](https://github.com/chenyiwang325-droid/toudi-workbench/releases) 安装并打开 TouDi。** 新用户使用独立空工作区；已有资料的用户在“设置 → 资料管理 → 选择已有工作区”接入原目录，经过检查后绑定。具体步骤见[桌面安装与使用](桌面安装与使用.md)。

**App 与 Agent 必须使用同一份正式资料。** App 升级不迁移资料，也不要求重新初始化。已有工作区的规则、准备、复盘、标记与信源更新流程应先读取并保留，不能用空模板覆盖。

## 2. 把信源和材料交给自己的 Agent

**在“设置 → 初始化与协作”复制流程，补充自己的来源和任务。** “复制通用流程”使用占位符；交给具备本机文件权限的 Agent 时，可以用“复制本机流程”取得工作区与资料工具位置。这些地址只供本机使用，不用于公开文档或展示。

| 你需要提供 | Agent 需要确认 |
| --- | --- |
| 招聘来源或已有记录 | 如何读取、何时更新，来源字段与原始链接如何保留。 |
| 简历、JD 或其他个人材料 | 哪些材料适用于这次任务，哪些事实仍缺少依据。 |
| 已有资料与规则 | 当前唯一母本、现有脚本与核验入口，哪些部分继续沿用。 |
| 求职偏好和任务范围 | 标签的真实含义、希望保留的方向，以及本次处理的公司、岗位或场次。 |

**Agent 使用你已有的工具环境与权限。** 本项目不内置模型，不要求额外购买 API，也不自动授权信源读取。没有本机工具权限的聊天工具可以先整理规范材料，由你手动导入；新增、导入和编辑入口始终保留。

## 3. 初始化信源规则

**先清点实际词条，再确认分类与筛选口径。** Agent 读取已有记录，或根据你授权的来源生成首批规范候选；按[内容与渲染契约](内容与渲染契约.md)核对字段、主体标识、日期与附件。不要先创建通用行业或学历列表，再把来源强行套进去。

**资料工具的 `preference-catalog` 命令只清点原词和出现次数。** 它不判定资格、不重写来源、不修改偏好。安装用户使用 App 提供的资料工具；以下命令仅展示源码形式：

```sh
python3 app/workbench.py --workspace /path/to/workspace preference-catalog
python3 app/workbench.py --workspace /path/to/workspace read settings
python3 app/workbench.py --workspace /path/to/workspace read edits
```

**初始化规则保存在当前工作区 `settings.preferenceRules`，与公开源码分开。** Agent 根据真实来源生成配置，使用公共 `validate → commit → read` 流程保存；先读取当前 settings 和版本，保留 `display`、`materialFiles`、`recordsAuthority` 等已有字段。命令参数与并发保护见[Agent 接入](Agent接入.md)。

| 配置 | 定义 |
| --- | --- |
| `schemaVersion` | 当前为 `1`。 |
| `directionMatch` | `any` 表示已选企业性质或行业满足一项；`all` 表示已选的两个维度均需满足。未选择的维度不限制结果。 |
| `dimensions` | 必须包含 `natures`、`industries`、`education` 三个维度。 |
| 每个维度的 `separator` | 来源明确使用的标签分隔符；空字符串表示保留整个原词。不能根据标点随意拆分学历条件。 |
| 每个维度的 `aliases` | 已确认同义的“原词 → 最终显示词”。不能把“本科及研究生”等不同含义自动当作“本科及以上”。 |
| 每个维度的 `groups` | 按来源定义的 `{name, values}` 分类；同一最终词条只属于一个分类。行业可先选大类再选细项。 |

**不同学历词条不自动换算成招聘资格。** 选择表示希望保留的已确认原词或同义词；来源缺失、新词、特殊要求或含义不明时继续保留。它们显示在“原始词条 · 待整理”，后续核对后补充规则。未初始化时采用保守显示，不猜测否定条件。

**首次初始化先核对规则，再运行一次小范围真实任务。** 检查原词是否保留、同义词是否等价、分组是否正确、已有标记是否完整；新旧来源并存时明确字段和标签口径。影响筛选含义或存在歧义的决定由用户确认，其他必要整理按已有授权完成。

## 4. 按任务开始协作

**日常按一个明确任务执行，不必重新配置整个工作台。** 更新记录、准备面试、探查岗位和复盘是独立流程；Agent 先读取最新母本与版本，只处理本次范围，再校验、保存、读回并核对 App 显示。任务输入与产出见[流程协作](流程协作.md)。

| 任务 | 应交付的结果 |
| --- | --- |
| 更新招聘记录 | 核对来源、日期和主体，保留已有进度、收藏与备注，发布本次候选记录。 |
| 准备面试 | 结合实际 JD、适用简历和已有问答，保存公司专项或通用准备。 |
| 探查岗位 | 保留事实、来源、判断和待核实事项，正文与附件关联完整。 |
| 复盘面试 | 基于真实记录还原问答，整理全场重点及必要改进，保存对应场次。 |

**Agent 保存后点击“刷新资料”，即可读取最新正文与初始化规则。** 有未保存编辑时保留本机草稿；版本冲突需要对账，不通过换版本号强行覆盖。App 和 Agent 使用同一资料锁与保存契约。

## 5. 日常保存与恢复

**普通编辑自动保存，只有换机或回退才需要备份操作。** “设置 → 资料管理”中的“保存备份文件”保存完整业务资料、设置和登记附件；“选择备份文件”先展示替换范围，确认后恢复；“查看历史修改”用于撤销误删或错误编辑。恢复完整文件可能覆盖其中更晚的改动，确认界面会说明范围，并自动保留恢复前内容。

**部署与资料管理分开。** App 是完整管理入口；其他设备只读查阅属于可选部署能力，由 Agent 按[首次使用与部署](首次使用与部署.md)处理，不在普通设置里提供加密导出。备份文件也不是可直接打开的网站。
