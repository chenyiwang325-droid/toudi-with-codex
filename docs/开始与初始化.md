# 开始使用 TouDi

**先打开 TouDi，再把自己的信源和材料发给 Agent，完成一次更新后即可开始日常使用。** TouDi 保存并展示结果；Agent 使用你现有的工具读取来源、整理资料与保存。你也可以在 App 中手动新增、导入和编辑。

## 1. 安装并打开 App

**从 [GitHub Releases](https://github.com/chenyiwang325-droid/toudi-workbench/releases) 下载适合自己系统的安装包，按[安装说明](桌面安装与使用.md)打开。** 新用户从空工作区开始，不必另装 Python 或启动服务。

**已有 TouDi 资料时继续使用原工作区。** 升级 App 不要求迁移或重新初始化；需要接入已有规范资料时，在“设置 → 资料管理 → 选择已有工作区”检查并绑定原目录。先保留原信源、规则、脚本和资料，再检查连接。

完成这一步后，应能打开投递管理、面试准备、岗位探查和面试复盘四个模块。空模块不表示故障，首次更新后才会出现你的资料。

## 2. 把信源和材料发给 Agent

**添加信源就是把来源交给你正在使用的 Agent，无需在 App 设置里另外创建来源。** 可以发送招聘网站链接、表格或文件，也可以说明已有的来源和更新方法。需要登录时，使用 Agent 原有浏览器或工具的授权方式，不把密码和访问密钥粘贴到消息里。

按这次任务提供必要材料：

| 你要做什么 | 发给 Agent 的内容 |
| --- | --- |
| 更新投递记录 | 招聘网站、招聘表格或已有记录文件；本次更新范围。 |
| 准备面试 | 公司、岗位、实际 JD 与这次使用的简历。 |
| 探查岗位 | 公司或岗位列表、希望核对的问题与可用来源。 |
| 复盘面试 | 录音逐字稿或真实纪要、公司与岗位、对应场次。 |

**让具备本机文件与命令权限的 Agent 处理 TouDi 资料。** 它使用随 App 提供的资料工具，读取当前持久绑定，不需要你再手动填工作区目录。只有聊天能力的工具可以先整理文件，再由你从对应模块导入。项目不要求额外购买模型 API。

## 3. 发送启动消息

**在“设置 → 开始与协作”点击“复制启动消息”，填好花括号中的四项，再与材料一起发送。** 也可以直接复制下面的消息：

```text
请帮我接入 TouDi 投递中控台，并完成下面这次任务。
开始指南：https://github.com/chenyiwang325-droid/toudi-workbench/blob/main/docs/开始与初始化.md

我的信源：{填写招聘网站链接、表格或文件；已有来源可写“沿用现有信源”}
我的材料：{填写简历、JD、面试记录等；暂时没有可写“暂不提供”}
本次任务：{先处理一份材料或几条记录，说明要更新、准备、探查或复盘什么}
已有资料：{填写“首次使用”或“沿用现有工作区和流程”}

请按以下顺序执行：
1. 先阅读开始指南。在我已授权的电脑上定位已安装的 TouDi 资料工具，运行 workspace status 确认当前绑定，再读取随包文档及工作区已有规则。无需让我重新填写目录；若无法访问，说明缺少的权限或材料，不扫描无关目录。
2. 读取我的信源，列出实际字段、原始标签、学历词条及更新方式。已有规则继续沿用；首次使用或新增来源时，用 preference-catalog 清点词条，只就会影响筛选含义的歧义向我确认，再保存自己的 preferenceRules。无法判断的词条保留原文。
3. 读取最新资料及版本，完成本次小范围任务，保留既有进度、收藏、备注和无关内容。候选先 validate，再 commit，最后 read 读回；版本冲突保留候选并对账。
4. 告诉我本次保存了什么、还有什么待确认，并让我在 App 点击“刷新资料”核对正文、标记与附件。后续沿用已确认流程，不重复初始化。

缺少事实时明确报告，不猜测日期、学历资格或个人经历。没有相应任务授权时，不提交网申、不对外沟通、不发布个人资料。
```

**已经在使用 TouDi 的用户，把“已有资料”写成“沿用现有信源与流程，先检查连接”。** Agent 读取并检查现有配置后即可执行本次任务，不能用首次使用模板覆盖你的原规则。

## 4. 确认必要分类，完成第一次任务

**Agent 应先告诉你读取到了哪些来源，以及哪些含义还需要确认。** 它清点实际字段、行业与企业标签、学历原词，提出有依据的分组和同义词归并；你只需确认有歧义或会改变筛选含义的部分。项目不提供作者的个人分类，也不把不同学历用词自动判成同一资格。

**第一次先处理几条记录或一份材料，确认能正确保存。** 已有工作区沿用原字段、脚本与核验步骤；新来源先生成符合[内容与渲染契约](内容与渲染契约.md)的候选，再验证和提交。无法判断的原词保留在“原始词条 · 待整理”，以后有依据时再补充规则。

完成后让 Agent 报告三件事：保存了哪些记录或材料、沿用了或新增了哪些规则、还有哪些内容待确认。实际读取、配置和保存命令供 Agent 参考，见 [Agent 接入](Agent接入.md)。

## 5. 刷新 App，核对结果

**点击 App 右上角“刷新资料”，到本次任务对应模块查看结果。** 更新记录看投递管理，准备稿看面试准备，探查报告看岗位探查，复盘看面试复盘。

首次核对以下内容即可：

- 本次记录或正文能看到，归属公司、岗位与场次正确。
- 原有进度、收藏、备注和其他材料仍在。
- 正文链接与附件可以打开；设置中的分类与词条和确认结果一致。
- 关闭并重新打开 App 后，资料仍可读取。

**App 和 Agent 使用同一份正式资料，业务更新无需重新安装 App。** 有未保存编辑时先处理草稿；保存遇到版本冲突时，让 Agent 读回差异并对账。

## 6. 以后直接安排任务

**日常直接告诉 Agent 要处理哪份来源或材料，不必重复发送启动消息。** 例如：

```text
更新这份招聘表中的记录，保留已有进度、收藏和备注。
根据这份 JD 和简历准备这场面试，保存到对应公司的面试准备。
核对这几个岗位的要求和来源，保存探查报告及附件。
复盘这份面试逐字稿，保存到对应场次。
```

**新增信源时，只补充该来源的读取方法、字段与分类规则。** 告诉 Agent 保留旧来源和旧规则；新词或缺失字段不能直接作为排除依据。更新、准备、探查、复盘各自的输入、产出与验收见[流程协作](流程协作.md)。

**普通编辑会保存；换机或需要回退时再使用备份。** “设置 → 资料管理”提供完整备份与历史修改恢复，具体范围见[备份与迁移](备份与迁移.md)。其他设备的只读查阅属于可选部署能力，见[首次使用与部署](首次使用与部署.md)。
