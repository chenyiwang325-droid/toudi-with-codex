# 开始使用：TouDi 与 Codex

**首次使用按“安装 App → 准备 Codex 与材料 → 初始化 → 配置 Luna → 完成一次任务”进行。** TouDi 保存并展示求职资料，Codex 负责根据你的信源和简历整理、更新，Chrome 扩展执行当前招聘网页的识别与填写。手动新增、编辑、导入和复制始终可用。

## 1. 安装并打开 TouDi

**从 [GitHub Releases](https://github.com/chenyiwang325-droid/toudi-with-codex/releases) 下载对应安装包，按[桌面安装说明](桌面安装与使用.md)打开。** App 自带运行组件，新用户从空工作区开始，不必另外启动 Python 服务。

**已有资料继续使用原工作区，不重复冷启动。** 在“设置 → 资料管理”检查当前连接；需要连接已有规范目录时选择“选择已有工作区”，先验证再绑定，保留原有信源、脚本、规则、标记与材料。升级 App 不要求重新整理简历或迁移数据。

完成后应能打开投递管理、面试准备、岗位探查、复盘和日程，侧栏“辅助填报”可维护个人资料。空模块使用对应的新增或导入入口开始。

## 2. 准备本机 Codex、信源与简历

**用 ChatGPT 账号登录本机 Codex，并提供本次需要的文件与命令权限。** 使用已安装的 Codex 桌面客户端或 CLI，官方安装与登录步骤见 [Codex 开始指南](https://learn.chatgpt.com/docs/quickstart)及[认证说明](https://learn.chatgpt.com/docs/auth)。本项目的插件核对使用该登录，不使用 API Key；仅有网页聊天权限的会话不能直接读写电脑工作区。

**先把自己的来源和材料交给 Codex，再让它整理资料。** 招聘信源可以是网站链接、表格或你指定的文件；简历和复用材料应使用本人已经确认的版本。不需要在 App 中重复填写一个来源配置表，也不需要提供与作者相同的来源。

| 本次任务 | 提供的内容 |
| --- | --- |
| 更新招聘记录 | 招聘网站、表格或记录文件，以及本次更新范围。 |
| 建立填报资料 | 完整简历、已确认的复用信息、适用资料版本和填写要求。 |
| 准备面试 | 公司、岗位、实际 JD、实际投递简历及本次要求。 |
| 探查岗位 | 公司或岗位列表、希望核对的问题与可用来源。 |
| 复盘面试 | 真实逐字稿或纪要、公司、岗位和场次。 |

**只提供本次任务需要的材料。** 暂时没有招聘信源时可以先建立填报资料或手动使用 App；登录网页沿用 Codex 原有工具的授权方式，不把密码或密钥粘贴到启动消息。

## 3. 让 Codex 完成初始化

**在“设置 → 开始与协作”复制启动消息，补充材料后发给 Codex。** 也可以复制以下内容：

```text
请作为我的 Codex 投递智能体，首次接入 TouDi，确认工具、工作区与现有资料。
开始指南：https://github.com/chenyiwang325-droid/toudi-with-codex/blob/main/docs/开始与初始化.md

招聘信源（可选）：{只有要更新招聘记录时才提供；暂不处理可留空}
我的材料：{填写简历、JD、面试记录等；暂时没有可写“暂不提供”}
接入后任务（可选）：{若需要，填写一份材料或几条记录的具体范围；没有则仅完成接入}
已有资料：{填写“首次使用”或“沿用现有工作区和流程”}

请按以下顺序执行：
1. 先阅读开始指南。在我已授权的电脑上定位已安装的 TouDi 资料工具，运行 workspace status 确认当前绑定，再读取随包文档及工作区已有规则。无需让我重新填写目录；若无法访问，说明缺少的权限或材料，不扫描无关目录。
2. 仅当本次涉及招聘记录或新增信源时，读取我的信源，列出实际字段、原始标签、学历词条及更新方式。以产品默认的行业层级和常用学历为基础，用 preference-catalog 核对实际词条；首次使用或新增来源时，只修正分类、同义词和明确学历范围的差异。已有规则继续沿用，只就影响筛选含义的歧义向我确认，再保存自己的 preferenceRules。地区、企业性质等附带信息不列为行业选项；MBA 等特殊、复杂或不明学历要求保留原文并兜底保留。
3. 有明确后续任务时，读取最新资料及版本，完成所指定的小范围任务，保留既有进度、收藏、备注和无关内容。候选先 validate，再 commit，最后 read 读回；版本冲突保留候选并对账。
4. 若本次需要辅助填报，对照我的完整简历维护 profile 资料，保留原文和整段经历的归属，不自行压缩。按辅助填报指南连接同一工作区，使用 ChatGPT 登录的本机 Codex；核对模型推荐 gpt-6-luna，只从实际模型目录选择并保存，不可用时报告，不换用 API 或其他模型。
5. 告诉我本次保存了什么、还有什么待确认，并让我在 App 查看更新或点击“刷新资料”核对正文、标记与附件。后续沿用已确认流程，不重复初始化。

缺少事实时明确报告，不猜测日期、学历资格或个人经历。没有相应任务授权时，不提交网申、不对外沟通、不发布个人资料。
```

**Codex 应先确认工作区，再完成有材料支持的初始化。** 它按[接入文档](Agent接入.md)定位随 App 提供的工具、读取当前绑定和已有规则；用户无需手抄本机目录。只有读取指定招聘信源时才清点真实字段、标签和学历词条，用 `preference-catalog` 对照默认分类，保存有依据的修正。

**默认分类可直接使用，纠偏只处理来源差异。** 行业保留“大类 → 细分方向 → 小类”；本科、硕士、博士等普通学历合并同义词。MBA、分岗位条件或含义不明的要求保留原文并兜底保留，不能因为用户选择普通学历而误排除。新来源只补差异，不重建已有规则或改变个人选中项。

**填报资料按通用表单建立，完整原文对应到具体经历。** Codex 对照简历维护个人、教育、实习、项目、校园经历、获奖和论文等模块，使用公共 `profile` 入口读取、校验、提交、读回。项目与实习描述不自行缩减；未知的身份、日期、学历和成果保留缺口，不自动补造。

## 4. 配置 Chrome 扩展与 Luna

**推荐通过本机 Codex 调用 GPT-6 Luna，核对填报中的字段语义和真实选项。** 从 Release 下载 `TouDi-browser-macos-arm64.zip`，按[辅助填报安装说明](辅助填报.md#安装与首次配置)加载扩展，并运行一次浏览器连接安装程序。

1. 在插件“资料与设置 → 资料管理”选择“连接当前工作区”，核对资料与 App 一致；双方内容不同时先保留候选、核对差异。
2. 在“Agent 协作”选择“本机 Codex”，点击“检查连接与模型”。
3. 从本机客户端实际返回的模型目录选择 **`gpt-6-luna`**，保存协作设置。已有明确模型选择继续保留，不自动更换。
4. 在一张招聘表单上进行一次核对，看到完成状态和最终结构化决定后，才算这次调用接通。

**模型目录存在不等于账号本次一定可调用。** Luna 不在目录、调用失败或额度受限时，保留本地计划；可以继续填写明确匹配的内容，或从“我的资料”复制。本项目不转用 API Key、不自动改用别的模型，也不要求新增模型服务。核对使用当前账号的 Codex 额度，套餐与模型可用性以官方账号状态为准。

**App 与扩展连接同一份填报母本，Luna 配置只作用于插件核对。** 资料连接不依赖模型登录；连接后 Chrome 按需启动工具，日常不必打开 TouDi App 或终端。正式资料保存在 `填报资料/资料.json`，浏览器离线修改先保留，恢复连接再同步。

## 5. 完成第一次任务并查看结果

**第一次先处理几条招聘记录、一份材料或一张表单，核对最终结果。** Codex 保存后读回并报告改动；App 自动接收已保存资料，也可以主动点击“刷新资料”。有未保存编辑的板块保留草稿，其他板块继续更新。

在中控台核对记录、正文、公司归属、进度和附件；确认原有收藏、备注及无关资料仍在。默认筛选分类与指定信源一致后，后续沿用，无需重新初始化。

**招聘表单按“识别 → 可选核对 → 自动填写 → 查看结果”操作。**

1. 点击 Chrome 的 TouDi 图标，浮窗自动只读识别当前页面，展示可填写、已一致和未匹配的内容。
2. 需要语义核对时点击“Agent 核对”。Luna 对照当前字段、真实选项和已有资料返回结构化决定；这一步不写入网页。
3. 点击“自动填写”，按整段经历绑定资料，补齐可确认的记录，填写并读回；也可选择“仅填空白”。明确日期和普通选项优先用本地规则，不要求先调用模型。
4. 查看网页最终值和未完成原因；无法自动处理的字段切换“我的资料”，按目录查找、点击复制完整内容。
5. 网页保存、附件上传和申请提交由你分别操作。填入不等于已提交，也不自动改变中控台投递状态。

## 6. 以后直接安排任务

**日常直接告诉 Codex 要处理哪份来源或材料，保留已有流程。** 例如：

```text
更新这份招聘表中的记录，保留已有进度、收藏和备注。
根据这份 JD 和实际投递简历准备面试，保存到对应公司。
核对这几个岗位的要求与来源，保存探查报告及附件。
复盘这份面试逐字稿，保存到对应场次。
对照我的简历补齐填报资料，保留完整描述和记录归属。
```

**新增信源时只核对它的读取方法、字段和分类差异。** 各任务的输入、输出与验收见[流程协作](流程协作.md)，具体管理命令见[Codex 接入](Agent接入.md)。手动修改也会正确保存；备份、换机和恢复见[备份与迁移](备份与迁移.md)。
