# 开发与贡献

**TouDi 以 Tauri 2 桌面 App 为默认入口，复用现有 HTML 和打包 Python 运行组件。** 同时保留 Python 本地/在线运行与加密只读快照；改动保持同一内容格式与公共保存逻辑。改动应保持真实内容、保存保护和实例之间的数据边界。

## 结构

- `app/投递管理.html`：空数据页面模板及模块渲染；运行时记录由服务注入。
- `app/`：本地/托管服务、桌面运行组件、公共资料管理与受限 Agent 接口。
- `desktop/`：Tauri 窗口、原生 API 桥接、运行组件生命周期和桌面打包。
- `render.yaml`：在线部署配置；持久磁盘与凭据由实例所有者管理。
- `Dockerfile`：已有容器平台的替代部署入口。
- `app/脚本/`：规范记录发布、准备/复盘解析、内容预检、探查目录及加密快照。
- `docs/`：使用契约与README 图文素材。展示内容不被运行时导入。
- `tests/`：创建临时工作区，验证启动、保护保存、导入及快照。
- `runtime/`：个人运行目录，忽略且不提交。

## 验证

```sh
python3 -m pip install -r requirements.txt
python3 -m unittest discover -s tests -v
python3 tests/check_source.py
```

可选 Actions 模板在 `docs/github-actions-check.yml`，当前未启用。它仅检查源码与隔离运行，不部署资料；需要时由具有工作流提交权限的维护者放入 `.github/workflows/check.yml`。

## 提交问题或改动

说明任务、实际行为、期望行为、浏览器/系统与最小复现步骤。截图与结构性复现资料必须匿名替换；不要上传自己的准备答案、附件、凭据或密文。UI 改动验证相关宽度、浅深主题、收起/展开、草稿与列对齐；写入改动验证版本冲突和范围保护。

先读 `AGENTS.md` 及对应内容/流程契约。不要批量重写资料、弱化加密或将展示内容注入默认工作区。新的信源适配应明确独立边界，不把某一用户的流程当默认规则。

## 桌面开发与构建

**构建环境需要 Python、Node.js、Rust 和目标系统的 Tauri 编译依赖。** 普通安装包用户无需这些工具。运行组件由 PyInstaller 打包，Tauri 使用系统 WebView 呈现原 HTML；资料保存在包外，不能将个人工作区纳入构建资源。

```sh
python3 desktop/scripts/build.py --help
# macOS 安装分发
python3 desktop/scripts/build.py --bundles app,dmg
# Windows 安装分发
python desktop/scripts/build.py --bundles nsis
```

**按构建脚本当前参数选择目标，跨平台构建与实机验收分开。** macOS 包内包含运行组件，App 接入说明生成工具路径；源码可用以下入口检查公共 CLI：

```sh
python3 app/desktop_runtime.py --workspace /path/to/workspace read records
```

**前端桌面模式通过 `window.__TOUDI_DESKTOP__` 获取工作区与工具位置并代理 API。** App 内使用稳定来源，避免动态内部端口改变显示配置与草稿的存储来源；不要将内部端口当作可公开服务地址。

**发布时记录实际系统、架构、签名与验收范围。** macOS 当前测试构建采用临时签名，未正式公证；Windows CI 构建成功不代替实机安装、退出重开、保存、备份恢复和 WebView2 检查。正式签名、公证与自动更新须对应实际实现再说明。

## 手动构建 CI

**仓库提供 [桌面打包 Actions 模板](github-actions-desktop.yml)，当前未激活。** 维护者具备工作流修改权限后，可将它放到 `.github/workflows/desktop-release.yml` 并手动触发。模板验证源码与打包运行组件，再构建 macOS arm64、macOS x64 和 Windows x64 的安装包与 SHA256 清单，只上传 Actions artifacts，不自动创建 Release。实际任务运行成功才构成对应 CI 构建证据，Windows 实机安装与保存仍需另行验收。
